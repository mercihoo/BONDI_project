# VR 썸스틱 연속 이동 트러블슈팅

- 담당: 김신정
- 환경: Unreal Engine, Enhanced Input, OpenXR, SteamVR, ALVR, Quest 2
- 관련 에셋: `IA_MoveStick`, `IMC_Move`

## 증상

컨트롤러 인식과 버튼 입력은 정상이고 블루프린트의 이동 함수도 동작했지만, 썸스틱으로 이동하려 하면 입력 축 값이 계속 `(0, 0)`으로 들어왔습니다. 이동 로직 자체보다 컨트롤러의 아날로그 축 입력이 Unreal까지 전달되는 경로를 확인해야 했습니다.

## 원인

`TESTPROJ`의 이동 액션 `IA_MoveStick`은 썸스틱의 X축과 Y축을 각각 나눈 입력 키로 설정되어 있었습니다. SteamVR/OpenXR가 `TESTPROJ`용 바인딩을 생성하는 과정에서 이 입력을 2D 썸스틱으로 제대로 해석하지 못했고, 그 결과 `IMC_Move`의 이동 바인딩이 비어 Unreal에 축 값이 전달되지 않았습니다.

즉, 컨트롤러 인식·버튼 입력·블루프린트 이동 함수는 정상이었고 입력 축 전달만 끊긴 상태였습니다.

```text
Quest 2 썸스틱
  → ALVR
  → SteamVR / OpenXR
  → TESTPROJ용 컨트롤러 바인딩
  → IMC_Move
  → IA_MoveStick
  → 블루프린트 이동 함수
```

## 해결

1. 이동 입력 키를 Quest 2용 2D 키인 `OculusTouch_Right_Thumbstick_2D`로 변경했습니다.
2. 다른 SteamVR 컨트롤러와의 호환을 위해 해당 컨트롤러용 2D 썸스틱 키도 함께 추가했습니다.
3. `TESTPROJ` 전용 SteamVR/OpenXR 바인딩 캐시를 초기화했습니다.
4. `ALVR → SteamVR → Unreal` 순서로 다시 실행해 SteamVR가 새 바인딩을 생성하도록 했습니다.

## 확인한 점

- 컨트롤러가 인식되고 버튼 입력이 정상이어도 아날로그 축 바인딩은 별도로 확인해야 합니다.
- X/Y를 개별 키로 구성한 설정이 런타임의 2D 썸스틱 바인딩과 일치하는지 확인합니다.
- 입력 키를 수정한 뒤에는 프로젝트별 SteamVR/OpenXR 바인딩이 갱신됐는지 확인합니다.
- 입력값이 다시 들어오는지 `IMC_Move`에서 `IA_MoveStick`까지 순서대로 점검합니다.

## 회고

썸스틱은 버튼과 달리 방향과 세기를 전달하는 아날로그 2D 입력이라, 컨트롤러 연결이 정상이어도 입력 키 설정과 런타임 바인딩이 맞지 않으면 축 값이 전달되지 않을 수 있었습니다. 입력 액션의 키를 2D 썸스틱 키로 맞추고 프로젝트별 바인딩을 새로 생성해 연속 이동 입력을 복구했습니다.
