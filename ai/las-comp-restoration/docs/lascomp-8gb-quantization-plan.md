## 1. 목표

굽다리바리의 결손 형상을 **LaS-Comp**(CVPR 2026, zero-shot 3D completion)으로 복원하고,
**이 노트북 8 GB에서 돌아가게** 만든다. 현재 기하 방식(`build_mesh_direct.py`)과
같은 지표로 비교해 채택 여부를 판단한다.

### 왜 LaS-Comp 인가

| 이유 | 근거 |
| --- | --- |
| **학습이 필요 없다** | training-free. 토기 학습 데이터가 없는 우리 상황에 맞는다 |
| **관측부를 보존한다** | ERS(Explicit Replacement Stage)가 관측 복셀을 입력값으로 직접 치환 → `NFR-ETH` 와 같은 요구가 방법론에 박혀 있다 |
| **백본이 TRELLIS** | A단계에서 이미 쓰는 모델. 가중치·개념이 이어진다 |
| 성능 | Omni-Comp 전 패턴에서 ComPC 대비 CD 49.6% 개선 |

### 이 모듈의 기존 전제가 바뀐다

`README.md` 는 "생성 모델을 안 쓴다"를 근거로 서 있다. LaS-Comp 을 쓰면 그 전제가 깨지고,
manifest 의 채움 영역은 **진짜로 `ai_inferred`** 가 된다. 이는 오히려 README 가 지적해 둔
"분류 칸이 실제와 안 맞는다" 문제가 해소되는 방향이다.

> **training-free ≠ AI 가 아님.** 백본 TRELLIS 는 대규모 사전학습된 rectified-flow
> 트랜스포머이고, IAS 단계는 occupancy BCE 손실로 **역전파를 돌린다**. 가중치를 안 고칠 뿐이다.

CUDA 툴킷(nvcc) 설치도 필요 없다** — kaolin 0.17/0.18(torch-2.4.0_cu121·cp310),
spconv-cu121 2.3.8, xformers 0.0.27.post2.

### 2.4 실행 흐름 (`run_lascomp_image_condition_single.py`)

```
입력 PLY 점군
  └─ voxelize_unit_cube(resolution=64)          → ss   (64³ occupancy)
        └─ avg_pool3d(kernel=4)                 → mask (16³)
              └─ pipeline.run_lascomp(mask, ss, image, ...)
                    ├─ outputs_ss   → sparse_structure.ply
                    └─ outputs_slat["mesh"][0]  → vertices / faces
```

- 입력은 **`.ply` 점군**, 조건은 **이미지 1장**
- 출력에 **메시가 직접 나온다** — 마칭큐브를 따로 짤 필요 없다
- `--optimization-step` **기본 1** ← IAS 반복 횟수. **메모리 지렛대가 여기다**
- 체크포인트 기본 경로가 `./ckpt/ckpt_image_large` 로, README 표기(`ckpt/image-large`)와 **다르다**

### 2.5 체크포인트 용량 — 조건 선택의 근거

| | DiT 가중치(FP16) | 전체 |
| --- | --- | --- |
| **image-large** | **2.3 GB** | 3.3 GB |
| text-xlarge | **4.1 GB** | 4.1 GB |

**이미지 조건이 DiT 기준 1.8 GB 가볍다.** 8 GB 에서 이 차이는 결정적이고,
마침 쓰려던 조건이 이미지(소장품 사진)다. **이미지 조건을 기본으로 한다.**

### 2.6 논문이 보고한 자원

peak **10.29 GB** (RTX 3090, FP16, batch 1) · 약 20 초/개 · denoise 100 스텝.
→ **약 2 GB 격차.** 이걸 메우는 것이 이 계획의 절반이다.

### 2단계 → 3단계 · 순서 변경

원래는 절감책을 한 칸씩 걸어 효과를 분리할 계획이었다. 기계가 죽는 상황에서는 그럴 여유가 없어
**안전한 것부터 전부 걸고 시작한 뒤, 여유가 확인되면 하나씩 되돌리며 개별 효과를 잰다.**

첫 조합(`run-lean.sh bimba fp8 0`):

| 절감책 | 기대 |
| --- | --- |
| 안 쓰는 디코더 2개 제거 | 327 MiB (실측) |
| FP8 양자화 — DiT 만 | 약 1.15 GB |
| IAS 0 회 | 역전파 활성값 제거 |
| `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` | 한계 근처 단편화 완화 |

**첫 조합 중간 관찰 (bimba, 13:36)**: SLAT 샘플링 23/100 스텝 시점 GPU **4674 MiB (57%)**,
2.9 초/스텝으로 정상 진행. 기준선 7941 MiB(97%) 대비 **약 3.3 GB 감소.** 어느 절감책이 얼마인지는
아직 못 가른다 — 여유가 확인된 뒤 하나씩 되돌리며 잰다.

훅 로그는 DiT 2개(`sparse_structure_flow_model`·`slat_flow_model`)를 양자화하고 디코더·인코더 3개를
유지, 이미지 인코더는 건너뛴 것으로 찍혔다 — 필터가 의도대로 동작. 다만 절감이 `0.0 MiB` 로 표시됐는데,
이는 torchao 의 `AffineQuantizedTensor` 가 겉 dtype 을 fp16 처럼 보여 `numel*element_size` 합산이
실제 저장 크기를 못 보는 계측 오류로 보인다(GPU 사용량 3.3 GB 감소가 그 근거). 안쪽 저장 텐서를
직접 더하고 GPU 할당량 전후를 함께 기록하도록 계측을 고쳤다.

**CPU 진단 결과 (`tools/diag_linear.py`, int8 로 기전 확인)** — 계측 오류가 맞았다.

| DiT | Linear | 변환 | 원래 | `element_size` 합산 | **실제 저장** |
| --- | --- | --- | --- | --- | --- |
| `sparse_structure_flow_model` | 196 | 146 | 1062 MiB | 1062 MiB (변화 없음) | **583 MiB** |
| `slat_flow_model` | 203 | 150 | 1148 MiB | 1148 MiB (변화 없음) | **665 MiB** |

가중치 클래스가 `Parameter` → `AffineQuantizedTensor` 로 바뀌었고, DiT 둘 합쳐 **약 962 MiB** 가 실제로 줄었다.
`(1024,1024)` 73개 · `(1024,4096)` 24개 · `(4096,1024)` 24개 등 큰 층이 대상.

**필터의 어긋남 하나** — 이름 규칙(`down_proj|fc2|proj_out|to_out|out_proj`)이 TRELLIS 에서는
어텐션 출력 `to_out`(48개)만 걸렀다. FFN down-projection 은 층 이름이 `mlp.2` 라 안 걸려서
첫 FP8 실행은 §5.2 의 의도와 **반대로** FFN down-proj 를 양자화하고 어텐션 출력을 남겼다.
모양(`in ≥ 2·out`)으로 FFN down-proj 를 잡도록 고쳤다(DiT 당 약 100 MiB 절감 포기).
비교용 `LASCOMP_QUANT_AGGRESSIVE=1` 이면 이 규칙을 끈다. 첫 실행 결과는 "aggressive" 로 분류한다.

**첫 조합 결과 (`lean-fp8-ias0-bimba`, aggressive 필터)** — ⟨Q2 실패, 그러나 위치가 밝혀졌다⟩

| 단계 | GPU 사용 | 비고 |
| --- | --- | --- |
| 희소 구조 샘플링 25 스텝 | — | 30 초 |
| SLAT 샘플링 100 스텩 | **4674 MiB (57%)** | 2.9 초/스텝, 정상 |
| **메시 디코딩** (`slat_decoder_mesh` → `group_norm`) | **7699 MiB (94%) 피크** | **`CUDA driver error: out of memory`**, 336 초 |

torch 할당 피크 7177 · 예약 7376 MiB. **OOM 이 난 곳은 DiT 가 아니라 메시 디코더다.** 샘플링 중 GPU 는
57% 였고 `decode_slat` 에 들어가며 약 3 GB 가 더 붙었다. 이 시점에 DiT 둘(FP8 로도 약 1.2 GB)·DINOv2
(약 0.6 GB)·희소구조 인코더/디코더(약 0.25 GB)는 할 일이 끝났는데 GPU 에 그대로 있다.

→ **디코딩 직전 오프로드 훅** 추가 (`LASCOMP_OFFLOAD=1`): `decode_slat` 을 가로채 `slat_decoder_mesh` 외
모델을 CPU 로 내리고 `empty_cache` 한 뒤 원래 디코딩을 부른다. 예상 확보량 약 2 GB → 피크 약 5.7 GB.
이 판단은 계획 §5.1 의 "IAS 활성값이 주범" 가설을 **기각**한다 — IAS 0 회에서도 디코더가 넘쳤다.
양자화(DiT)는 샘플링 구간의 여유를 만들었고, 디코딩 구간은 **오프로드**가 맞는 도구다.

**두 번째 조합 (`lean-fp8-ias0-off1-bimba`, 보수 필터 + 디코딩 전 오프로드)** — ⟨Q2 실패, 다시 한 단계 더 깊이⟩

| 항목 | 값 |
| --- | --- |
| FP8 (보수 필터) | Linear 122/196 · 123/203 변환, **실측 -776 MiB** (계측 수정 후 정확히 잡힘) |
| 오프로드 | 5개 모델 CPU 로 → GPU 할당 **4473 → 1607 MiB (-2866)** |

디코딩 경로가 1.6 GB 에서 출발해 7 GB 까지 간다 = **디코더+FlexiCubes 가 혼자 약 5.5 GB.**

처음 세운 가설("IAS 때문에 grad 가 켜진 채 디코딩돼 활성값이 남는다")은 **코드로 기각** —
`run_lascomp` 는 이미 `@torch.no_grad()` 다. 남는 설명은 **dense 그리드 자체**다: 메시 디코더(`decoder_mesh.py`)가
64³ 잠재를 `self.upsample` 블록으로 키운 뒤 `SparseFeatures2Mesh` 가 `construct_dense_grid(res)` ·
`get_dense_attrs(res+1)` 로 **정방 격자를 통째로** 만든다. res 가 256 이면 큐브 1,670 만 개 — 인덱스(int64 ×8)만
약 1 GB, 속성(sdf·deform·weights·color, fp32)이 수 GB. 양자화·오프로드는 이 구간에 힘이 없다.

남은 지렛대 (다음 조합):
1. **FlexiCubes 를 CPU 에서** — 디코더 신경망은 GPU, dense 격자·메시 추출만 CPU (`LASCOMP_MESH_CPU=1`). 느리지만 확실. RAM 이 넉넉해야 한다(31 GB, 29 GB 여유 확인).
2. dense 속성 fp16 — 절반 절감, SDF 0-교차 정밀도 위험.
3. 해상도 낮추기는 **불가** — 디코더 출력 좌표가 그 해상도에 묶여 있다.

**해석.** 64³ 복셀 한 칸이 물체의 1.6% 다. 굽다리 투창의 살(기둥)은 그보다 가늘어서 희소 구조 단계에서 사라지고,
디코더는 그 자리를 "받침"이라는 사전지식으로 메운다 — 계획 §6 위험 1 "64³에서 투창 소실"이 **그대로 실현**됐다.
반면 그릇 몸통(큰 곡면, 반복 띠)은 이 모델이 잘하는 영역이라 설득력 있게 이어졋다.

**따라서 LaS-Comp 의 쓸 자리는 정해진다:**
1. **그릇 몸통의 큰 결손을 채우는 데만** 쓴다. 굽다리·투창은 기존 기하 방식(`build_mesh_direct.py`, 회전대칭 + n-fold 주기)이 맞다.
2. 최종 산출은 **합성**: 관측 영역 = 원본 메시 그대로(관측부 이탈 25% 를 그대로 내보낼 수 없다), 결손 = 부위별로 LaS-Comp(몸통) / 기하(굽다리).
3. 아직 시험 안 한 지렛대: IAS 스텝 2~3(경계 정합 강화), 텍스트 조건 병행("Korean pedestal bowl with rectangular openwork"), seed 3 개. 각 7 분.

- Subdivide 블록: skip 을 먼저 계산해 `sub(x)` 를 즉시 버리고, `out_layers` 를 한 층씩 불러 `sub(h)` 가 첫 컨볼루션 뒤에 풀리게 한다.

### 2단계 실행의 정확한 절차 — 저자 코드 기준 (`run_lascomp_image_condition_single.py` · `samplers/flow_euler.py::sample_lascomp`)

`run_args.txt`: dataset=custom · yz_flip=True · normalize_partial=True · preprocess_image=True · seed=1 · rescale_t=3.0 · alpha_eta=0.1 · optimization_step=1 · lr_sample=1e-5.

1. **점군 로드** `partial.ply`(원본 GLB 표면 10 만 점) → y·z 교환(Y-up → 모델 내부 Z-up) → 중심·최대 변으로 단위 정육면체 [-0.5, 0.5] 정규화 (center·scale 보관).
2. **복셀화** 64³ 점유 `ss`(관측 복셀) · `avg_pool3d(k4,s4) > 0` 로 16³ `mask`(잠재 해상도의 관측 영역).
3. **조건 이미지** RGB → 최대 1024 → rembg(u2net) 배경 제거 → 알파 bbox 1.2 배 정사각 크롭 → 518×518 → 알파 곱(검은 배경) → **DINOv2 ViT-L/14-reg** 특징 = cond.
4. **희소 구조 샘플링 (ERS + IAS)** FlowEuler + CFG 1.0(구간 0.5~1.0) · **100 스텝** · rescale_t 3.0 · 잠재 16³×8ch. 매 스텝:
   v 예측 → x₀ = s − t·v, x₁ = s + (1−t)·v → (t>0.5 이면 x₁ 에 η=0.1·t 만큼 잡음, 비관측 영역은 새 잡음)
   → **ERS**: decoder(x₀) > 0 로 64³ 복셀 예측 → **관측 복셀을 1 로 강제** → encoder 로 다시 잠재 x₀' → s = (1−t)·x₀' + t·x₁
   → **IAS**(1 회): s 에 grad 걸고 Adam(lr 1e-5) — loss = 관측 복셀에서만 BCE(decoder(s − t·v), ss) → 1 스텝
   → v 재예측, 오일러 s −= (t−t_prev)·v.  끝나면 decoder(z) > 0 → **47,740 복셀**.
5. **구조 잠재(SLat) 샘플링** `slat_flow_model`(DiT-L, **FP8 가중치**) 을 그 47,740 자리에서 **25 스텝** · CFG 1.0 → 복셀당 8ch 잠재.

## 5. 양자화 — 실행 방법

### 5.1 어디를 줄이는가

LaS-Comp 의 메모리는 셋으로 나뉘고, 양자화가 듣는 곳은 하나뿐이다.

| 구성 | 양자화 효과 |
| --- | --- |
| TRELLIS DiT 가중치 (image-large 기준 **2.3 GB**) | **크다** — FP8 이면 절반(약 1.15 GB 절감) |
| ERS 의 clean/noisy 두 분기 잠재값 | 작음 |
| **IAS 역전파 활성값** | **거의 없음** → 2단계로 대응 |

### 5.2 적용 범위 — 반드시 나눈다

| 대상 | 처리 | 이유 |
| --- | --- | --- |
| DiT (`slat_flow_img_dit_L`, `ss_flow_img_dit_L`) | **FP8 로 내린다** | 가중치 대부분이 여기 |
| VAE · 디코더 (`slat_dec_*`, `ss_dec_*`) | **FP16 유지** | 기하를 실제로 만들어내는 곳. 여기서 깎으면 표면에 티가 난다 |
| FFN down-projection | **제외** | 확산 모델 양자화에서 품질 유지의 핵심 지렛대로 보고돼 있다 |

### 5.2.1 torchao 버전 — 두 제약을 동시에 만족해야 한다

| 제약 | 이유 |
| --- | --- |
| `Int4WeightOnlyConfig` 가 있어야 한다 | transformers 4.55.2(저자 핀)가 torchao 가 **설치돼 있으면** 그 이름을 import 한다. 없으면 transformers 자체가 깨진다 |
| torch 2.4.0 에서 돌아야 한다 | 0.12.0 이상은 torch 2.5+ 를 기대해 import 에서 실패 |

실측: **0.10.0 · 0.11.0 만 통과.** 0.5.0 은 Config 클래스가 없어 transformers 를 깨뜨리고, 0.12.0 · 0.13.0 은 torch 2.4 에서 import 가 실패한다. **`torchao==0.11.0` 을 `--no-deps` 로 고정**한다 (torch 를 밀지 않게).

### 5.3 왜 FP8 인가

RTX 4070 Laptop 은 **sm_89** 라 FP8 이 하드웨어로 지원된다(torchao 요구선 ≥8.9).
확산 모델에서 FP8 이 속도·메모리·품질 절충이 가장 좋고, **품질은 fp16 에 근접하며
INT8 보다 나은 경우가 많다**고 보고돼 있다.

### 5.4 실행

```bash
# 기준선 (양자화 없음)
python tools/measure_vram.py --label baseline -- \
  run_lascomp_image_condition_single.py \
    --partial-path samples/<샘플>.ply --image-path samples/<샘플>.png \
    --dataset custom --yz-flip

# 2단계 — IAS 끄기
python tools/measure_vram.py --label no-ias -- \
  run_lascomp_image_condition_single.py ... --optimization-step 0

# 3단계 — FP8 (DiT 만, 디코더 제외)
LASCOMP_QUANT=fp8 python tools/measure_vram.py --label fp8-dit -- \
  run_lascomp_image_condition_single.py ...
```

양자화는 `tools/quantize_trellis.py` 가 `TrellisImageTo3DPipeline` 을 감싸
DiT 모듈만 골라 변환한다. 환경변수 `LASCOMP_QUANT` 로 켠다 (`off` | `fp8` | `int8`).

### 5.4.1 도구 (`~/work/LaS-Comp/`, 저자 코드는 건드리지 않는다)

| 파일 | 역할 |
| --- | --- |
| `quantize_trellis.py` | `from_pretrained` 훅 — DiT 만 FP8/INT8 (`LASCOMP_QUANT`), `decode_slat` 훅 — 디코딩 전 오프로드 (`LASCOMP_OFFLOAD=1`). 어텐션 to_out · FFN down-proj(모양 `in ≥ 2·out`) 제외, `LASCOMP_QUANT_AGGRESSIVE=1` 이면 전부 |
| `tools/measure_vram.py` | 저자 스크립트를 runpy 로 그대로 돌리며 nvidia-smi 피크(WSL 은 GPU 전체) + torch 피크 기록. driver OOM 으로 컨텍스트가 죽어도 보고서를 남긴다 → `vram_reports/<라벨>.json` |
| `tools/run-lean.sh OBJ QUANT IAS OFFLOAD` | 한 설정 실행. 라벨 `lean-<q>-ias<n>-off<0/1>-<obj>` |
| `tools/eval_completion.py` | Q3 Chamfer(정규화·프레임 두 가지 중 작은 쪽, 채택 프레임 기록) · Q4 관측부 보존(입력 점→결과 표면 거리, 복셀 1칸 밖 비율) → `eval_reports/` |
| `tools/ablate.sh OBJ "q ias off" ...` | 설정을 순서대로 하나씩 돌리고 산출물이 나오면 바로 평가, `ablation_summary.md` 표로 모음 |
| `tools/diag_linear.py` | CPU 진단 — 필터가 고른 Linear 수, 양자화 전후 가중치 클래스와 실제 저장 바이트 |

운영 메모: 긴 실행을 `| tr` 같은 파이프에 물리면 **끝날 때까지 출력이 버퍼에 갇혀** 진행을 못 본다.
로그는 파일에 직접 쓰고 읽을 때 정리한다. WSL 에서는 `nvidia-smi` 프로세스별 사용량이 `[N/A]`.

### 5.4.2 다음 실험 순서 (`run-lean.sh OBJ QUANT IAS OFFLOAD MESHCPU`)

1. `fp8 0 1 1` 이 메시를 내면 → **Q1 통과.** 곧바로 `eval_completion.py` 로 Q4(관측부 보존) 확인.
2. `off 0 1 1` — 양자화 없이 오프로드+CPU 추출만. 들어가면 **Q3 의 비양자화 기준**이 생긴다. 안 들어가면 "양자화가 필요하다"는 증거.
3. `fp8 1 1 1` — IAS 를 다시 켠다. 논문 설정 복원 가능한지.
4. `int8 0 1 1` — FP8 대비 품질·메모리.
5. `fp8 0 1 0` — CPU 추출을 끄고 GPU 추출로. FlexiCubes 격자가 정말 결정적이었는지 확인(안 들어가야 정상).
6. 표(`ablation_summary.md`)를 §4 에 옮기고 채택 설정을 정한 뒤 굽다리바리로.

`tools/ablate.sh bimba "fp8 0 1 1" "off 0 1 1" "fp8 1 1 1" "int8 0 1 1" "fp8 0 1 0"` 한 줄로 순차 실행된다
(GPU 는 하나라 병렬은 없다). `ablate.sh` 의 삼중항은 `run-lean.sh` 인자 수에 맞춰 **오중항**으로 갱신해야 한다.

### 5.5 대안 — mmgp

FP8 로 부족하면 [`deepbeepmeep/mmgp`](https://github.com/deepbeepmeep/mmgp)
(8비트 + 파이프라인 오프로드). 같은 방식으로 만든 Hunyuan3D-2GP 가 6 GB 미만에서 돈다.
다만 **TRELLIS 2 에서 디코딩 때 메모리가 튄다**는 이슈가 열려 있어 시간이 더 들 수 있다.
