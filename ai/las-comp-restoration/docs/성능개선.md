# 성능 개선

LaS-Comp 복원 파이프라인에서 **무엇이 문제였고, 무엇을 바꿨고, 얼마나 나아졌는지**의 실측 기록.
저자 코드(LaS-Comp/TRELLIS)는 한 줄도 고치지 않았다 — 전부 런타임 훅 또는 후처리다.

## 요약

| 개선 | 전 | 후 | 근거 |
| --- | --- | --- | --- |
| **투창 보존** (ERS 양방향) | 창 2개 · 채움 97.1% | **창 10개 · 86.6%** | §1 |
| 8GB 진입 (디코딩 절약) | OOM (디코딩 피크 7,350 MiB) | **3,276 MiB** | §2 · [양자화 문서](양자화내용%20수치로%20비교.md) |
| 채움부 질감 | 모델 예측색 = 무채색 한 톤 | 원본 실측 텍스처 전사 | §3 |
| 서버 미리보기 색 소실 | 화면에서 단색 | UV 2048² 로 구워 해결 | §3 |
| 채움부 결 | 반사가 닿지 않는 곳은 민민함 | 원본 결의 **통계로 합성** | §3-4 |
| 실행 시간 (같은 유물·설정) | 697 초 | **473 초** | §1 |

## 1. 투창 보존 — ERS 를 양방향으로 ★ 이번 핵심

### 1-1. 증상

굽다리(대) 투창이 복원 결과에서 통째로 메워졌다. 원본 스캔에는 2단 8개가 뚫려 있는데
복원본은 통짜 원통이 된다. 가이드 이미지에 투창을 또렷하게 그려 넣어도 막혔다.

### 1-2. 첫 진단은 틀렸다

처음에 "투창은 64³ 격자에서 **폭 2~3복셀**뿐이라 FlexiCubes 가 양쪽 벽을 이어 버린다"고 판단했다.
거친 잣대(고정 26×72칸)로 **짐작한 것**이고 측정한 적이 없었다.

격자 1칸을 복셀 1개에 맞춰 다시 재니 **투창은 7~16복셀 폭**이었다 — 64³ 에서 충분히 크다.
해상도는 원인이 아니었다.

### 1-3. 실제 원인 — 단계별 측정

굽다리 벽을 원통으로 펼쳐(1칸 ≈ 1복셀) 단계마다 빈 구멍을 셌다.

| 단계 | 채운 칸 | 남은 창 |
| --- | --- | --- |
| ① 원본 점군 (모델 입력) | 74.4% | **7개** (16×12 · 11×7 · 11×7 · 10×5 · 7×6) |
| ② 1단계 복셀 64³ | 92.7% | **2개** |
| ③ 2단계 LaS 메시 | 97.1% | 2개 |

**①→② 에서 잃는다.** 2단계(표면 추출)는 거의 그대로다. 즉 **모델이 64³ 격자를 만드는 순간** 메운다.

왜 그런가 — LaS-Comp 이 관측을 강제하는 장치가 **둘 다 한쪽 방향**이다:

```python
# ERS — 매 스텝 (trellis/pipelines/samplers/flow_euler.py)
pred_voxel = (decoder(x_0) > 0.0).float()
pred_voxel[voxel_mask] = 1.0        # 관측된 칸을 1 로만 만든다
```

- **ERS**: "관측된 칸은 차 있어야 한다"만 강제. 관측되지 않은 칸을 0으로 묶는 코드가 없다.
- **IAS**: BCE 손실도 **관측 복셀에만** 걸린다. 빈 칸의 손실은 0이다.

빈 공간에 제약이 전혀 없으니 그 자리를 TRELLIS 의 생성 사전분포가 채운다. 학습 데이터에
통짜 굽다리가 뚫린 굽다리보다 압도적으로 많으니 기본값이 "채운다"가 된다.
실측 로그에서도 스텝마다 복셀 수가 **늘기만** 한다 (32,411 → 32,955).

가이드 이미지가 안 듣는 이유도 이것이다 — 조건은 확률을 기울일 뿐, **"비어 있어야 한다"는 하드 제약이 아니다.**

### 1-4. 고친 방법

**투창과 결손을 구분하는 것**이 핵심이다. 점군만 보면 둘 다 "관측이 없는 곳"이라 같아 보인다.
구분되는 성질은 **갇힘**이다:

- **투창** — 사방이 관측된 표면으로 둘러싸인 빈 구멍
- **결손** — 파단면을 따라 위·아래로 **열려** 있다

그래서 `tools/ers_keep_empty.py` 가 굽다리 벽을 원통으로 펼쳐(1칸 ≈ 1복셀)
**테두리에 닿지 않는 빈 덩어리만** 골라, 그 자리의 벽 두께 범위(±2복셀) 안 복셀을
"비어 있어야 한다"로 확정한다. 결손부는 테두리에 닿으니 제외되고, 관측 복셀은 교집합에서 빼
ERS 의 1 고정과 충돌하지 않는다.

강제하는 방법 — **저자 코드를 고치지 않는다.** ERS 는 `(decoder(x_0) > 0.0)` 로 점유를 정하므로,
**희소 구조 디코더의 로짓을 그 칸에서만 −1e4 로 눌러** 두면 매 스텝 자동으로 0이 된다
(`quantize_trellis.install_ers_empty_hook`). 샘플링 뒤 최종 구조를 뽑는
`argwhere(decoder(z_s) > 0)` 에도 같은 억제가 걸려 결과까지 유지된다.

```
LASCOMP_KEEP_EMPTY=1          켠다 (기본 꺼짐)
LASCOMP_KEEP_EMPTY_PAD=2.0    벽 두께 여유 (복셀)
LASCOMP_KEEP_EMPTY_MINCELLS=4 이보다 작은 구멍은 잡음으로 보고 무시
```

마스크 실측 (굽다리바리): 세로축 자동 검출 축2 · 굽다리 슬라이스 2~25 · 격자 24×92 ·
벽 반지름 중앙값 14.6복셀 · **갇힌 구멍 6개 → 비어야 하는 복셀 716개** (관측 17,563개)

### 1-5. 결과

같은 유물(`new20260911_03`)·같은 가이드·같은 시드·같은 설정(τ 0.6 · 섬 0.2% · 질감 k12 g0.8),
차이는 `LASCOMP_KEEP_EMPTY` 하나.

| 단계 | ERS 기본 | **ERS 양방향** |
| --- | --- | --- |
| ① 원본 점군 | 74.4% · 창 7개 | 74.4% · 창 7개 |
| ② 1단계 복셀 | 92.7% · 창 **2개** | **82.4% · 창 9개** |
| ③ 2단계 메시 | 97.1% · 창 **2개** | **86.6% · 창 10개** |

창 크기도 원본과 맞는다 (11×6 · 8×6 · 10×6 · 10×6 · 7×6 복셀).

**부작용은 없고 오히려 전부 좋아졌다:**

| | ERS 기본 | ERS 양방향 |
| --- | --- | --- |
| LaS 면 | 997,912 | 973,492 |
| 채움 (원본 면적) | 48.1% | **43.1%** |
| 유지 조각 | 6 / 123 | 5 / 128 |
| 관측부 보존 중앙값 | 0.00858 | **0.00759** |
| 관측부 보존 p95 | **0.02340** | 0.02409 |
| 복셀 1칸 밖 비율 | 17.12% | **16.55%** |
| 걸린 시간 | 697.0 초 | **473.1 초** |
| VRAM 피크 | 4,631 MiB | **4,566 MiB** |

- 채움이 5%p 줄었는데 **줄어든 것이 전부 덮지 말아야 했던 굽다리**다.
- 관측부 보존 중앙값과 복셀 1칸 밖 비율이 개선됐다 — 원본 파단면을 덜 밀어냈다는 뜻.
- p95 만 0.0234 → 0.0241 로 미세하게 나빠졌다 (0.3% 차이). 눈에 보이는 변화는 아니다.
- **시간이 32% 빨라졌다.** 빈 칸이 확정되니 모델이 그쪽에서 헤매지 않는 것으로 보인다.

### 1-6. 같은 문제의 대안 — 높이 필터

`composite.py --ymin auto` 로 굽다리를 채움 대상에서 빼는 방법도 있다 (몸통·굽다리 목을
둘레 반지름 최소로 자동 검출 — 굽다리바리에서 bbox 높이의 0.383).

| | 채움 (원본 면적) | 투창 띠 |
| --- | --- | --- |
| 기본 | 48.1% | 99.6% · 창 6개(잡음 크기) |
| 높이 필터 | 32.4% | 57.1% · **원본과 완전히 동일** |
| **ERS 양방향** | **43.1%** | 86.6% · 창 10개 |

높이 필터는 확실하지만 **굽다리의 진짜 결손도 못 채운다**. ERS 양방향은 굽다리를 채우면서
투창만 지키므로 더 낫다. 굽다리가 심하게 깨진 유물이면 양방향을, 굽다리가 온전하면 둘 중 아무거나.

## 2. 8GB 진입 — 디코딩 절약 재구성

이미지 조건 + IAS 1 로 굽다리바리를 돌리면 **7,350 MiB 에서 OOM** 이었다. 양자화·오프로드·
메시CPU 를 다 켜도 났다. 원인은 디코더 업샘플 2단계의 `SparseGroupNorm32` — 입력이
3.05M × 96 채널인데 fp32 사본을 여러 개 만들어 **입력의 약 8배**를 잡았다.

두 모듈의 `forward` 를 갈아끼워 고쳤다 (통계는 fp64 누적, scale/shift 를 채널로 접고,
**4 MiB(2²²) 조각 단위로 제자리 연산**).

| | 디코딩 피크 | 프로세스 피크 |
| --- | --- | --- |
| 훅 없음 | 7,350 MiB → **OOM** | 6,588 MiB |
| 훅 있음 | **3,276 MiB** | **4,529 MiB** |

수치적으로 같은 결과를 낸다 — 근사가 아니라 재구성이다 (`tools/test_decode_lean.py`).
자세한 내역과 양자화·오프로드·메시CPU 의 기여도는 [양자화내용 수치로 비교.md](양자화내용%20수치로%20비교.md).

## 3. 채움부 질감

### 3-1. 모델 예측색은 쓸 수 없었다

조건 이미지가 회색 무광 렌더면 예측 색도 무채색 한 톤이 된다.

| 가이드 | 예측색 1~99 백분위 | 폭 |
| --- | --- | --- |
| 회색 무광 (guide6) | 0.216 ~ 0.364 | 0.148 |
| 회색 무광 (guide9) | 0.091 ~ 0.332 | 0.241 |
| **질감 있는 렌더** (guide10) | 0.134 ~ 0.653 | **0.519** |

질감 가이드를 넣으면 폭이 2배 이상 넓어지고 색조도 청회색(B>G>R)에서 도자기다운 따뜻한 쪽
(R>G>B)으로 바뀐다. 그래도 절대값이 어두워(평균 66) 원본 실측(평균 145)과는 거리가 커서
**실측 텍스처 전사를 계속 쓴다.**

### 3-2. 원본 실측 텍스처를 이어 붙인다

물레로 돌린 그릇은 같은 높이대의 표면 통계가 회전 방향으로 같다. 이 성질로 파단면을 거울 삼아
인접 실측 표면을 결손부로 반사한다 (`tools/texture_fill.py`).

실측: 채움 정점의 **88.5~91.1% 가 반사로 채워지고**, 표본까지의 거리 중앙값이
0.0052 → **0.0018** (약 3배 감소).

### 3-3. UV 텍스처로 구워 서버 문제를 없앴다

자료 서버가 만드는 경량 미리보기에서 채움부 색이 사라졌다. 원인:

```
prim[0] (원본, 텍스처)  COLOR_0 = 255,255,255 전부 흰색   COLOR_1 = 0,0,0
prim[1] (채움)          COLOR_0 = 255,255,255 전부 흰색   COLOR_1 = [151,144,133] ← 실제 질감
```

Blender 가 원본(텍스처)과 채움(정점 색)을 한 오브젝트로 합칠 때 **텍스처 메시용 흰색 더미
색 속성이 COLOR_0 을 차지하고** 실제 채움 색이 COLOR_1 로 밀린다. three.js 는 COLOR_0 만 읽는다.

`tools/bake_fill_texture.py` 로 채움부를 원통 펼치기 UV + 2048² 텍스처로 구워 정점 색 의존을
없앴다. 덤으로 텍셀 밀도가 원본과 같아졌다 (정점 색 34만 개 ≈ 원본의 1/7 → 1:1).
이음선은 ±π 를 가로지르는 면의 꼭짓점을 복제해 `u+1` 로 두어 없앴다 (실측 1,321면 · 675꼭짓점).

> **서버 쪽 버그는 그대로 남아 있다.** 우회했을 뿐이다. `blender_preview.py` 에서 합친 뒤
> 전부 흰색인 색 속성을 지우고 의미 있는 쪽을 활성/렌더 인덱스로 지정하면 근본 해결이다.

### 3-4. 결을 원본 통계로 합성한다

거울 반사(3-2)는 채움 정점의 88.5~91.1% 만 닿는다. 남는 곳은 결이 없어 민민하고,
반사 배율을 키우면 얼룩·쐐기가 보였다. 그래서 **결의 출처를 원본 자기 텍스처의 통계**로 바꿨다
(`bake_fill_texture.py --grain-source`).

1. 원본 표면을 표본 추출(기본 16M 점)해 채움 텍스처와 **같은 (u=θ, v=h) 격자**에 관측 이미지를 만든다.
   원본이 덮는 텍셀 62.1%(굽다리바리). 표본이 안 떨어진 포아송 구멍은 **표면 영역 안에서만** 최근접으로 메운다.
2. **완전히 관측된 64×64 창 1,960개**에서만 방사 평균 파워 스펙트럼(결의 굵기)과
   고역 밝기 히스토그램(명암 분포)을 잰다. 부분 관측 창을 섞으면 경계가 결로 잡힌다.
3. 그 통계로 텍스처 격자 전체에 결을 합성한다 — 스펙트럼을 맞춘 가우시안 잡음에 **순위 맞춤**으로
   밝기 분포를 입힌다. FFT 로 만들어 **둘레 한 바퀴가 주기**라 `u` 순환에서 이음선이 없다.

적합 대상이었던 관측 영역 통계는 그대로 재현된다:

| | R | G | B |
| --- | --- | --- | --- |
| 원본 관측 이미지의 결 std | 12.66 | 12.80 | 12.96 |
| 합성된 결 std | **12.66** | **12.80** | **12.96** |

완성된 GLB 를 다시 재면(원본 1024² · 채움 2048², 고역 σ 를 변 길이에 비례시켜 **같은 공간 대역**으로 비교):

| 산출물 | 결 std (R,G,B) | 평균 밝기 (R,G,B) |
| --- | --- | --- |
| 원본 실측 텍스처 | 10.83 · 11.17 · 11.02 | 127.8 · 118.1 · 99.3 |
| 채움 (`--grain-source`, 무보정) | 12.74 · 12.87 · 13.04 | 131.3 · 121.3 · 102.1 |
| 채움 (`--tint 1.12`, 사이트에 올린 V4) | 14.27 · 14.42 · 14.60 | 146.6 · 135.4 · 113.8 |

**무보정판은 톤이 원본과 +3 안쪽으로 붙는다.** 결은 원본 텍스처 전체 기준으로는 +1.7~2.0 높게 읽히는데,
결을 적합한 대상이 1024² 원본 텍스처가 아니라 **원통 관측 이미지**이기 때문이다 — 두 값은 서로 다른 것을 잰다.

V4(×1.12)는 수치를 맞추려고 올린 것이 **아니다**. 원본 텍스처의 높이별 색이 아가리 [151,145,128] ·
몸통 [122,110,92] 로 실제로 다르고, 채움이 그것을 그대로 따르면 수치는 맞지만 **살아있는 원본 조각 옆에서
어두워 보인다.** 표현상의 선택이고, 그래서 무보정판을 함께 남긴다.

#### 곁다리로 잡은 것 둘

- **재질 유효값.** 박물관 스캔은 `metallicFactor 1 · roughnessFactor 1` 인데 metallicRoughness
  텍스처가 B=0 · G=255 라 **유효값은 metallic 0 · roughness 1** 이다. 채움은 텍스처 없이 factor 만
  갖고 있어 금속처럼 어두웠다. 이제 `factor × MR 텍스처 평균` 을 채움에 준다.
  (서버 뷰어는 `viewer.js` 가 값을 덮어써 화면에는 영향이 없지만 Blender 썸네일과 다른 뷰어에는 보인다.)
- **톤의 표본 편향.** 높이대 중앙값을 정점 표본으로 잡았는데, 사진측량 메시는 어두운 틈·굽다리에
  정점이 몰려 면적 가중보다 어둡다 — 굽다리 높이대에서 13~16 어두웠다. `--tone-source 1` 은
  원통 관측 이미지의 **행 중앙값(면적 가중)** 을 쓴다. 채움 평균 [128.6,117.9,98.9] → [131.2,121.2,102.3].
- `--tone-side outer`(법선이 바깥인 표본만)도 재 봤지만 132.2 → 133.4 로 +1 뿐이라 **원인이 아니었다.**
  선택지로만 남긴다.

**남은 과제** — 톤이 높이대 중앙값이라 안쪽 면(원본은 녹회색)이 바깥 톤으로 나온다.

## 4. 측정 방법 — 재현하려면

```bash
# 투창 단계별 측정 (격자 1칸 = 1복셀, 굽다리 구간·회전축 자동 검출)
python tools/ers_keep_empty.py --partial samples/artifacts/<이름>/partial.ply --out-dir <출력>

# ERS 양방향 켜고 복원
LASCOMP_KEEP_EMPTY=1 IMAGE_OVERRIDE=<가이드>.png REFTAG=keep \
TAU=0.6 MINAREA=0.002 TEXMODE=blend TEXK=12 TEXGAIN=0.8 \
  bash tools/run-gupdari.sh fp8 1 1 <이름>
```

**판정 순서는 몸통 폐합(눈) → 채움량 → Q4 다.** Q4(관측부 보존)만 보면
**아무것도 안 한 모델이 1등**이 된다 — 실제로 "보존 최고"로 보고한 실행의 렌더에서
테두리가 찢어져 있었다.

투창은 눈으로만 보면 놓친다 — 굽다리 접사를 따로 뽑아 보고, 위 격자 측정으로 창 개수를 센다.

## 5. 막혔던 것 (다음 사람 시간 아끼기)

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 훅이 설치되지 않음 (`AttributeError`) | 런타임이 import 하는 `quantize_trellis` 는 `tools/` 가 아니라 **저장소 루트**의 파일 (`measure_vram` 이 repo_root 를 sys.path 에 넣는다) | 루트에도 복사 |
| 훅은 붙었는데 마스크가 안 만들어짐 | 파이프라인이 부르는 건 `sample_sparse_structure` 가 아니라 **`lascomp_sample_sparse_structure`** | 둘 다 감싼다 |
| `coord_mode="raw"` 로 `KeyError` | 허용값은 `auto` / `none` / `swap_yz` / `negx_swap_yz` | `auto` 사용 |
| 셸 스크립트가 파싱 오류 | Python 으로 파일을 고칠 때 Windows 줄바꿈(CRLF)이 들어감 | `newline="\n"` 으로 쓰기 |
| 오프스크린 렌더가 검게 나옴 | WSL 의 GPU EGL(mesa d3d12)이 색 버퍼를 전부 0으로 돌려줌 | `LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe` |

## 6. 남은 것

- **투창 이외의 뚫린 구조** — 지금 마스크는 굽다리 구간의 원통 펼치기에서만 찾는다. 몸통에 뚫린
  구조(예: 손잡이 구멍)가 있는 유물은 못 잡는다. 3D 전역에서 "갇힌 빈 덩어리"를 찾는 쪽으로 넓힐 수 있다.
- **IAS 도 양방향으로** — 지금은 ERS 만 고쳤다. IAS 의 BCE 에 빈 칸 항을 더하면 정렬도 함께 개선될 여지가 있다 (미시도).
- **IAS 반복 2~3회** — 테두리 정렬이 나아질 여지가 있으나 확인하지 않았다 (피크 +318 MiB · 시간 +55%).
- **FP8 + text-xlarge NaN** — XL DiT 만 NaN. 미해결, 양자화 없이 우회 중 (`tools/diag_fp8_nan_layer.py`).
- 이음새 띠(파단선 따라 생기는 색 경계)와 아가리 테두리 단.
