# gupdari-shape-prior — 여러 굽다리바리로 만드는 통계 형상 모델

유물 **한 점**이 아니라 **한 갈래**를 다룬다. 그래서 유물별 폴더
(`gupdari-71489`, `bitsal-ssu022891`) 와 나란히 두지 않고 따로 뒀다.

## 왜 만드나

2026-09-12 굽다리바리 71489 를 MCP 로 복원했을 때, 단면 프로파일을 **깨진 그 유물
자신에게서** 뽑았다 (바깥을 보는 정점의 z 구간별 80분위수). 남아 있는 데선 잘 됐는데
한 군데가 비어 있었다:

> **아가리는 둘레 전체가 톱니로 깨져 있었다.** 입지름도 아가리 높이도 참고할 온전한
> 부분이 하나도 없어서, 남은 데까지의 곡선을 그냥 이어 올렸다.

`meta/artifacts.csv` 가 이걸 뒷받침한다 — 71489 의 `크기` 는 **`높이 15.0cm` 뿐이고
`입지름` 이 없다.** 박물관도 못 적은 것이다.

여기가 추정이었다. 같은 갈래 43점을 모으면 추정이 아니라 **통계**가 된다.

## 무엇을 만드나

```
랜드마크(대응점) -> 정렬 -> PCA -> 통계 형상 모델
   "같은 자리"     크기·위치   변동 압축   평균 + 주성분
```

산출물은 **평균 고배 + 주성분 몇 개**다. 어떤 고배든

    평균 + a1*(1번 변형) + a2*(2번 변형) + ... + a6*(6번 변형)

으로 근사된다. 프로파일 100개 숫자가 **6개로** 준다.

복원에 쓰는 법: 깨진 유물은 100개 중 70개만 남아 있다. 형태가 6차원 위에 산다면
**70개로 a1~a6 을 최소제곱으로 맞추면 나머지 30개가 따라 나온다.**

### 참고한 구조

`L-GAN 3D : 3D 얼굴 모델링을 위한 랜드마크기반 GAN 모델`
(현선영·하영국·이경숙, 차세대융합기술학회논문지 2023, 7(11), 1798-1806)

| 단 | 논문 | 여기 |
| --- | --- | --- |
| 구조 사전 | 얼굴 랜드마크 | 프로파일 위 구조 전이점 7~8곳 |
| 통계 모델 | 3DMM (얼굴 스캔 PCA) | **고배 프로파일 PCA** |
| 생성 | GAN | (1차엔 없음. PCA 가 곧 모델) |
| 3D 로 올림 | 3D-Optimizer | (r,z) 윤곽 회전 — 이미 있다 |

**3DMM 이 곧 PCA 다.** 정렬된 얼굴 스캔을 모아 주성분을 뽑은 것. 43점으로 GAN 은 무리지만
PCA 는 충분하다. 표본이 늘면 그때 GAN 을 같은 칸에 끼워 넣으면 된다.

# 1단계 결과 (2026-09-12)

`extract_silhouette.py` · 43장 처리 · `plain` 27점 중 **23점 통과**.

## 알아낸 것 — 실루엣이 기록 입지름보다 **일관되게 좁다**

| | 값 |
| --- | --- |
| 부호 있는 오차 중앙 | **-15.0%** (실루엣이 좁다) |
| 절대 오차 p75 | 18.0% |
| 10% 이내 | 18건 중 5건 |

한쪽으로만 치우쳤다 = 우연이 아니라 **계통 오차**다. 원인은 촬영 각도다.

카메라가 각 t 만큼 위에 있으면 아가리가 타원으로 보이고, **뒤쪽 테두리가 위로 솟아
실루엣의 세로 길이가 유물 높이보다 길어진다**:

```
겉보기 세로 = H·cos(t) + D·sin(t)          <- 높이보다 길다
겉보기 가로 = D                            <- 가로는 줄지 않는다
```

그래서 `높이 ÷ 세로픽셀` 로 축척을 잡으면 cm/px 가 **작게** 나오고, 폭이 좁아진다.
관측된 부호와 정확히 같다.

기록된 `높이`·`입지름`으로 t 를 역산하면 **중앙 10.2도 · 사분위 7.2~13.9도**.
t=10도, H=9, D=11.2 를 넣으면 보정 계수가 1.20 — 관측된 -15~-21% 와 맞아떨어진다.

**결론: 2단계 원근 보정은 선택이 아니라 필수다.** 그리고 고칠 방법도 정해졌다 —
축척을 **높이가 아니라 가로폭**으로 잡고 (가로는 foreshortening 이 없다),
z 를 `1/cos(t)` 로 편다. t 는 아가리 타원의 단축/장축에서 직접 잰다.

## 정정 — 굽(바닥)은 믿을 수 없다

> "step1 그림자 같은 바닥도 뽑아 버리는데 이거 맞아?"

맞는 지적이었다. 확인해 보니 **앞 절의 1단계 보고는 아가리에 대해서만 맞는 말**이었다.

### 무엇이 잘못됐나

1. **그림자 버리기가 한 번도 작동하지 않았다.** 맨 아래에서 위로 올라오며 넓은 줄을
   버리도록 짰는데, 그림자는 아래로 갈수록 뾰족해진다. 첫 줄에서 바로 멈춰
   `버림` 이 27장 전부 **0** 이었다. 그래서 마스크 바닥 = 그림자 끝이 됐다.
2. **자르기는 그림자를 없애지 않는다, 줄일 뿐이다.** 아가리 폭으로 잘라 놓으면
   굽 자리에 실제보다 넓은 **통짜 기둥**이 남는다.
3. 그 결과 받침지름을 아는 2건에서 바닥폭이 **-22%**, 일부는 굽이 아예 사라졌다
   (경주 2027 바닥폭 0.68cm · 경주 8480 0.26cm).

### 고치려다 더 나빠진 세 가지

| 시도 | 결과 |
| --- | --- |
| 넘친 줄부터 아래 전부 버리기 | **27~45% 를 날려** 굽이 사라지고 축척이 뒤집힘 (신수 16068 +64%) |
| 덩어리 내부 Otsu 로 유물/그림자 가르기 | 조건 미달로 대부분 거부, 작동한 경우 악화 (증 873 좌우차 5.6 -> 33.2%) |

그림자의 배경거리 `d` 분포가 **유물의 어두운 부분과 겹친다.** 한 문턱으로 안 갈린다.

### 다음에 할 것 — 규칙을 더 만지지 않는다

v1~v7 을 거치며 분명해졌다. 배경·조명·유물 색이 제각각인 사진 43장에서
**손으로 짠 규칙으로는 그림자와 유물이 안 갈린다.** 정확히 학습 모델이 이기는 종류의 문제다.

1. **`rembg` (U^2-Net) 로 배경 분리.** 사전학습 모델이고 그림자에 강하다. CPU 로 돈다.
   43장을 한 번에 처리한 뒤 **지금 지표(입지름 오차 · foot_bad)로 규칙 기반과 비교**하면
   그 자체가 "규칙 vs 학습" 비교 기록이 된다.
2. 그래도 안 되는 몇 장은 **손으로 칠한다.** 27장은 손으로 감당되는 수다.

지금 상태로도 **아가리~몸통은 쓸 수 있다.** 굽이 필요한 3단계 랜드마크 8곳 중
1·2번(굽 바닥테)은 5점에서만 나온다.

## 물어봤어야 할 질문 — 그 한 숫자에 사진 27장이 필요한가

이 폴더를 만든 목적은 하나였다: **71489 의 아가리**. 둘레 전체가 깨져 자기 자신에게서
뽑을 수 없고 박물관도 `입지름` 을 못 적었다.

그런데 실루엣을 뽑기 전에 확인했어야 할 게 있었다. `meta/artifacts.csv` 에 높이와
입지름을 **둘 다 가진 굽다리바리가 20점** 있다. 고배는 한 갈래의 기물이니 둘이 상관될 것이다.

`rim_from_records.py` — 사진을 한 장도 안 쓰고:

```
상관계수 r = 0.946  (r^2 = 0.896)
입지름 = 0.933 x 높이 + 2.654
leave-one-out 오차 중앙 0.64cm · p90 2.04cm · 상대 5.4%
```

**회귀 한 줄로 끝난다.** 실루엣 추출·원근 보정·랜드마크 정렬·PCA 다섯 단계가
이 목적에는 필요 없었다. 먼저 물어봤어야 했다.

복원본이 예측보다 **1.83cm (11%) 좁다.** LOO p90 이 2.04cm 이니 경계선이지만,
아가리가 통째로 결실된 유물에서 남은 곡선을 **보수적으로 이어 올린** 결과로 보인다.
실제 고배는 아가리가 더 벌어진다 (입지름/높이 비 중앙 1.183, 복원본은 0.987).

## 이 폴더의 현재 위치

**보류.** 형상 사전은 "프로파일의 절반 이상이 사라진 유물"에 필요한 도구다.
71489 는 프로파일이 대체로 살아 있어서 회전대칭 뼈대 + 위 회귀로 충분했다.

남긴 것:
- `rim_from_records.py` — 실제로 쓸 수 있는 결과
- `meta/artifacts.csv` — 43점 치수·투창 구조 표 (계속 쓸모 있다)
- `_seg.py` v1~v7 실패 기록 — **규칙으로 안 갈리는 문제**의 사례

## 규칙 vs 학습 — 분리 문제는 학습이 이겼다

> "근데 실루엣 추출부터 잘 안됐는데"

맞다. 그래서 손으로 짠 규칙을 빼고 **사전학습 모델(rembg / U^2-Net)** 을 같은 자리에 끼웠다.
사진도 측정 코드도 지표도 그대로, **분리 방식만 교체**했다 (`SEG=rembg`).

`compare_backends.py` · 굽다리바리 27점:

| | 규칙 v3 | rembg |
| --- | --- | --- |
| 관문 통과 | 23 | **26** |
| **굽 오염 0% 인 것** | **8** | **27** |
| 덩어리 1개인 것 | 5 | **26** |
| 좌우차 중앙 | 8.5% | **3.6%** |
| **굽오염 중앙** | **41.1%** | **0.0%** |
| 입지름 오차 중앙 | 16.3% | **13.2%** |
| 앙각 추정 사분위폭 | 8.3도 | **3.9도** |

**굽 오염이 전 유물 0% 다.** v1~v7 내내 못 뗀 그림자가 한 번에 사라졌다.
앙각 추정의 사분위폭이 절반으로 준 것도 같은 이야기다 — 측정이 흔들리던 이유가
알고리즘이 아니라 **입력 마스크**였다.

### 왜 여기선 학습이 이겼나

빗살무늬토기에서는 **반대**였다. 거기선 규칙(축 회전 전사)이 U-Net 을 이겼다
(이면각 4.22도 vs 6.92도). 차이는 실력이 아니라 **문제에 쓸 구조가 있느냐**다.

| | 이용할 구조 | 이긴 쪽 |
| --- | --- | --- |
| 결실부 표면 잇기 | 회전체는 **회전에 대해 자기 자신** | 규칙 |
| 그림자 vs 도자기 | **없다** — 한 화소만 보면 둘 다 '배경보다 조금 어두운 회색' | 학습 |

그림자를 가르려면 **무엇이 물체인지** 알아야 한다. 그건 국소 규칙으로 못 쓰고
데이터에서 배워야 하는 지식이다. 문턱값을 일곱 번 만진 것은 없는 규칙을 찾은 셈이다.

### 틀린 게 아니라 맞아서 나빠진 숫자 하나

`경신 71489` 만 좌우차가 24.2% -> **62.4%** 로 올라 관문에서 떨어졌다. 그런데 이게 맞다.
71489 는 배신 절반이 결실된 유물이라 **실제로 좌우가 그만큼 다르다.**
규칙판은 그림자로 빈자리를 메워 비대칭을 **가리고 있었다.**

지표가 나빠진 것이 모델이 나빠진 증거가 아닐 때가 있다.

### 실행

