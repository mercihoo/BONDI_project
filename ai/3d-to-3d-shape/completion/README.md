## 한눈에

**쓴 데이터 — 굽다리바리 완형 19형상 · 2,280쌍.** 형상 단위로 나눴다 —
학습 14형상(1,680쌍) · 검증 2형상(240쌍, 에폭 선택) · **테스트 3형상(360쌍)**.
쌍 단위로 나누면 같은 유물이 학습과 평가에 같이 들어가 의미가 없다.
테스트 3형상은 학습에도 에폭 선택에도 안 썼다 (자세히: [결과.md](결과.md) §5.15).

학습에 쓴 16점은 42점에서 셋으로 걸러 9점을 썼고(v2),
v3 에서 사진을 다시 보며 **7점을 더했다.** 더한 7점은 아가리가 깨져 입지름을 못 재지만
`(h,θ)` 격자 결손률로는 완형이다 (자세히: [데이터.md](데이터.md))

![선별 깔때기](images/데이터-선별-깔때기.png)

![완형 16점](images/데이터-완형-사진.png)

**결과 — 벤치마크 누출을 찾았고, 프로토콜을 고친 뒤 파인튜닝이 통했다** (자세히: [결과.md](결과.md))

> **핵심 발견.** `partial` 을 `complete` 의 좌표계로 정규화하면 **모델이 원래 크기를
> 액자에서 읽는다.** 같은 쌍·같은 가중치로 정규화만 바꾸니 커버리지 순증이
> **0.700 → 0.102** 로 무너졌다. ShapeNet-55 벤치마크가 그렇게 만들어져 있고,
> **그게 실제 유물에서 완성 모델이 무너지는 이유다** (결과.md §4.5).

**성능 — 테스트 세트(학습·에폭선택에 안 쓴 3형상 · 360쌍) · 결손 깊이별 F순증**

| 결손 깊이 | 쌍 | 사전학습 | v1 | v2 | **v3** | v3−v2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.00~0.20 | 136 | 0.641 | 0.899 | 0.836 | 0.895 | +0.060 |
| 0.20~0.35 | 34 | 0.082 | 0.702 | 0.702 | **0.867** | +0.165 |
| **0.35~0.50** (71489 수준) | 51 | 0.082 | 0.438 | 0.586 | **0.936** | **+0.350** |
| 0.50~0.65 | 21 | 0.026 | 0.229 | 0.625 | **0.918** | +0.292 |

**71489 는 아가리에서 아래로 높이의 40~50% 가 손상돼 있다** —
h 0.6 위로 결손이 40~81% 다. 위 표의 `0.35~0.50` 구간이 그 수준이다.

**F순증 = 재현율과 정밀도의 조화평균** (바닥값 보정). **둘을 같이 봐야 한다** —
무작위로 점을 뿌리는 대조군이 재현율만 보면 `side` 에서 **1.000** 을 받는다
(정밀도는 0.042). 자세히: [결과.md](결과.md) §5.14

**깊이별로 봐야 한다.** 쌍의 절반이 결손률 0.20 미만이라 전체 중앙값은
**쉬운 구간에 앉는다** — 그렇게 보면 v1 이 0.902 로 괜찮아 보이는데
깊은 결손에서는 **0.229** 다.

**v3 의 이득은 전부 깊은 쪽에 있다.** 얕은 결손에서는 v1 과 사실상 동률이다.
v3 = 완형 9→16 형상 + `slant`(비스듬한 절단) 패턴.
v2 는 순증만 보면 v1 보다 나은데 **정밀도가 낮아** F순증으로는 v1 에 진다 (§5.14).

`slant` 만 0.485 → **0.985**. 나머지 패턴은 그대로라 **잃은 것이 없다**.

**실제 유물 — 계속 좋아지지만 합성만큼은 아니다**

| **71489** 가 만든 새 점 | 사전학습 | v1 | v2 | **v3** |
| --- | ---: | ---: | ---: | ---: |
| 출력 8,192점 기준 | 20 | 253 | 388 | — |
| **회전 TTA 8회 (65,536점)** | — | — | 2,946 | **5,185** |

![71489 점군 v3](images/결과-71489-점군-v3.png)

맨 오른쪽 `v32` 는 **회전대칭을 가정해** 통째로 만든 것이다 — 대조군이다.
이 파이프라인은 그렇게 하지 않는다.

## 어떻게 도나 — 점을 찍고, 격자로 채운다

**모델이 만드는 것은 점뿐이다.** 면도 두께도 색도 모델이 만들지 않는다 — 그건 메시화가 한다.

```
입력  점 2,048개        ──[AdaPoinTr]──▶   출력 점 8,192개 (회전 TTA 8회 → 65,536)
                                              │  87~92% 는 입력을 다시 그린 것
                                              │   8~13% 가 **새로 만든 점**
                                              ▼
                                    (h, θ) 격자 144x216 에 올린다
```

![점과 격자](images/설명-점과격자.png)

| | |
| --- | --- |
| **어디를 메울지** | **관측 점군이 빈 칸**(A). 투창은 빼고 |
| **어떤 모양으로** | 그 칸의 **모델 점** 반지름 |
| 모델 점이 없는 칸 | **이웃에서 보간** — A 의 34% 가 여기 해당한다 |

**모델이 새 점을 찍은 칸(B)은 A 안에 완전히 들어간다** (A 밖 0칸).
관측이 있는 자리에는 새 점을 안 만든다는 뜻이다.
그런데 B 는 A 의 3분의 1밖에 안 덮는다 — 출력이 8,192점으로 고정이라
결손이 넓으면 성길 수밖에 없다. **회전 TTA 가 필요한 이유가 이것이다.**

> **3D 회전체를 2D 로 펴서 푼다.** 구멍 메우기·평활·텍스처가 전부 2D 연산이 된다.
> 그림의 가로가 각도 한 바퀴, 세로가 높이다.




### 8,192점은 결손부용 예산이 아니다

모델은 **완성된 그릇 전체**를 8,192점으로 그린다. 결손부만 그리는 게 아니다.

| 한 번 추론 · 8,192점 | |
| --- | ---: |
| 이미 있는 관측을 **다시 그린 것** | 약 **7,544점 (92%)** |
| 결손부에 떨어진 **새 점** | **648점 (7.9%)** |

그래서 결손이 넓으면 성길 수밖에 없다 — 예산의 92%가 이미 아는 곳에 쓰인다.
**회전 TTA 가 필요한 이유가 이것이고**, 그래도 결손 칸의 28% 밖에 못 덮어
나머지를 보간이 메우는 이유도 이것이다.

### 격자가 깔고 있는 가정 — 축에서 한 방향에 표면 하나

![격자 가정](images/설명-격자가정.png)

`(h,θ) → r` 로 펴려면 **축에서 한 방향을 봤을 때 표면이 하나**여야 한다.
이걸 셋으로 갈라 두면 헷갈리지 않는다.

| | 무엇을 가정하나 | 누가 쓰나 |
| --- | --- | --- |
| 완전 회전대칭 | `r = f(h)` — 각도와 무관 | **v32 대조군.** 이 파이프라인은 **안 쓴다** |
| **축에 대해 별 모양** | `r = f(h, θ)` — 한 방향에 표면 하나 | **격자가 요구하는 것** |
| 가정 없음 | 임의의 메시 | 푸아송·볼피벗 같은 표면재구성 |

**71489 에서 얼마나 지켜지나** (48x72 로 성글게, 표본 넉넉한 2,340칸)

| 칸당 반지름 무리 | 칸 | |
| --- | ---: | --- |
| 1개 | 25.0% | 홑겹 — 테두리·굽 바닥 |
| **2개** | **66.6%** | 안쪽벽 + 바깥벽. 이 그릇의 정상 상태 |
| 3개 이상 | **8.4%** | **가정을 벗어난다** |

벗어나는 자리가 한 곳에 몰려 있다 — **h 0.30~0.45 에서 37%**.
**굽다리와 바리가 만나는 곳**이다. 축에서 쏜 선이 굽다리 벽을 지나고
그 위 바리의 밑면을 또 지난다.

**두 겹(66.6%)도 사실 칸 하나에 안 들어간다.** 격자는 반지름을 하나만 담으므로
`--outer-shift` 로 **바깥벽에 맞추고**, 안쪽벽은 `wall_thickness` 가 단면의 빈틈을
찾아 **따로 세운다**. 두 겹까지는 그렇게 우회하고 있다는 뜻이다.

> **이게 통하는 이유는 2노드 분리에 있다.** 관측이 남은 곳은 `region_observed` 로
> **원본 메시가 그대로** 나간다 — 이음부의 여러 겹도 손대지 않는다.
> 격자는 **새로 만드는 면**만 표현하면 된다.
> 바꿔 말하면 **결손이 이음부에 걸치면 이 가정이 바로 문제가 된다.**
> 손잡이·귀때·뚜껑처럼 축에서 별 모양이 아닌 기종도 마찬가지다.

### 회전 TTA — 점군을 축 둘레로 돌려 여덟 번 추론한다

![회전 TTA](images/설명-회전TTA.png)

입력은 3D 점 2,048개의 **좌표 배열**이다. 그 배열을 축 둘레로 45°씩 돌려
여덟 번 추론한 뒤 **−45°k 로 되돌려** 합친다. 렌더링도 카메라도 거치지 않는다.

```python
for k in range(8):
    a = 2*pi*k/8
    q = rot_about(pts, up, a)        # 점 좌표를 돌린다
    o = infer(model, q)              # 추론
    outs.append(rot_about(o, up, -a))  # 되돌린다
```

**왜 여러 번 하나 — 이유가 둘이다.**

| | |
| --- | --- |
| **출력 수가 학습 시점에 박혀 있다** | AdaPoinTr 은 무조건 **8,192점**을 낸다. 한 번 추론으로는 못 늘린다 |
| **모델이 회전 불변이 아니다** | 같은 물체를 돌려 넣으면 **다른 답**을 낸다. 71489 에서 회차별 새 점이 592~722개 (변동계수 0.06) |

돌린 것이 같은 물체인 이유는 **이 유물이 회전체**라서가 아니다 — 무엇을 돌리든
같은 물체다. 회전체라는 사실은 여덟 답이 **서로 어긋날 이유가 없다**는 뜻이고,
그래도 어긋나는 만큼이 곧 **모델 분산**이다.

**실제로 얼마나 버나** (71489 · 결손 후보 11,740칸)

| | 1회 | **8회** |
| --- | ---: | ---: |
| 출력 점 | 8,192 | **65,536** |
| 결손 칸을 덮은 비율 | 5.2% | **28.0%** |
| 점 사이 거리 (최근접 중앙) | 2.04mm | **0.92mm** |

> 8배를 돌렸는데 점 간격은 2.2배만 촘촘해진다 (이론값 √8 = 2.83).
> 출력의 **87~92% 는 입력을 다시 그린 것**이라 회차끼리 크게 겹치기 때문이다.
> 새로 버는 것은 나머지 8~13% 뿐이다.

**그래도 28% 다.** 나머지 72% 는 격자의 이웃 보간이 메운다.
격자가 144x216 = 31,104칸인데 한 번 추론이 8,192점이니 애초에 다 채울 수가 없다.

### R 격자를 어떻게 채우나 — AI 점이 먼저, 회전체는 나중에 섞는다

![메시 생성](images/설명-메시생성.png)

칸 하나의 값 `R[h,θ]` 는 그 칸에 떨어진 **AI 점의 반지름 중앙값**에서 출발한다.
거기서 네 단계를 거쳐 최종 R 이 된다.

| 단계 | 무엇을 하나 | 왜 |
| --- | --- | --- |
| ① 점 → R | 칸에 떨어진 AI 점의 반지름 중앙값 | **이게 뼈대다** |
| 점이 없는 칸 | 이웃 칸에서 보간 (`fill_unknown`) | 출력 8,192점으로는 칸을 다 못 채운다 |
| 바깥벽 정렬 | 행마다 목표 반지름으로 민다 (`--outer-shift`) | 칸 중앙값은 벽 **한가운데**라 그냥 쓰면 파묻힌다 |
| ② 회전체 블렌드 | 그 높이의 중앙 반지름 쪽으로 당긴다 (`--axisym 0.85`) | 모델 출력이 깊은 안쪽에서 거칠다 |
| ③ 격자 → 면 | 칸 네 귀 → 삼각형 두 장 | 격자가 이웃을 알고 있다 |

②의 세기는 **고정이 아니다.** 이음새(관측과 붙는 곳)에서 0 이고 안으로 들어갈수록
6칸에 걸쳐 0.85 까지 오른다. 71489 에서 **전체 평균 0.33** — 즉 **3분의 2 는 점, 3분의 1 이 회전체**다.

**보간도 회전 가정이 아니다.** `fill_unknown` 은 위·아래·좌·우 **네 이웃의 평균**을
반복하는 라플라스 평활이라, 높이 방향과 각도 방향을 똑같이 본다. 재보면:

| 71489 · 보간한 4,041칸 (패치의 30%) | |
| --- | ---: |
| 보간 결과가 **그 행의 중앙 반지름**(=회전체)과 다른 정도 | 중앙 **1.24mm** · 90분위 **3.62mm** · 최대 **12.47mm** |
| 회전 가정이었다면 | **0mm** |
| 참고 — 같은 높이에서 점 반지름이 실제로 흔들리는 폭 | 11.0mm |

> 다만 **결과는 회전체에 가까워진다.** 결손이 θ 로 넓으면 가장 가까운 기지값이
> 같은 높이의 다른 각도이기 때문이다. **가정이 아니라 기하가 그렇게 만든다.**
> 중앙 1.24mm 는 같은 높이의 자연스러운 흔들림(11.0mm)의 11% 다.

재면서 하나 고쳤다. 야코비 반복이라 경계의 영향이 한 번에 한 칸씩 퍼지는데
71489 의 가장 넓은 결손은 θ 로 **196칸**이다. 기본 400회로는 가장 깊은 곳이
**최대 1.56mm** 덜 수렴했다 (800회 0.18mm · 2000회 0.01mm). 비용이 0.08 → 0.18초라
**1000회로 올렸다.**

> 왜 섞나. 이음새에서 회전체를 쓰면 관측 조각과 **어긋난 턱**이 생긴다.
> 깊은 안쪽에서 점만 쓰면 모델 출력이 거칠어 **이면각이 28°** 까지 뛴다 (관측 6.0°).
> 그래서 붙는 곳은 점을, 먼 곳은 회전체를 믿는다.

**왜 격자인가 — 푸아송·볼피벗 대신 이걸 고른 이유 셋**

| | |
| --- | --- |
| ① **어디를 메울지 정해준다** | *"점이 없는 칸 = 결손"* 이라는 규칙이 생긴다. 투창은 거기서 예외로 뺀다. 점군만 들고는 *"여기가 구멍인지 원래 뚫린 것인지"* 를 말할 방법이 없다 |
| ② **3D 문제가 2D 영상 문제가 된다** | v22 빌드 20여 단계 중 **14단계가 격자 위 2D 연산**이다 — 가우시안 평활, 모폴로지 닫기, 라플라스 보간, 대역통과(돌대), 연결성분 라벨링. 3D 메시에서 하려면 하나하나가 따로 어려운 문제다 |
| ③ **관측과 AI 를 안 섞는다** | 푸아송을 쓰면 관측 점과 AI 점이 **한 덩어리 표면으로 녹는다.** 그러면 *"어디까지가 유물이고 어디부터가 추정인가"* 를 못 가른다. 격자는 칸 단위로 출처를 들고 있어 `region_observed` 를 **원본 메시 그대로**(V=94,877 F=149,150 무수정) 내보낼 수 있다 |

③ 이 결정적이다. 문화재에서 출처 분리는 있으면 좋은 기능이 아니라 **요건**이다
(NFR-ETH-003). 표면재구성을 쓰면 그 요건부터 못 지킨다.

**대신 격자 자체가 가정을 하나 깔고 있다** — `(h,θ) → r` 이 함수가 되려면
축에서 한 방향에 표면이 하나여야 한다. 완전 회전대칭보다는 약하지만
**가정이 없는 것은 아니다** (바로 위 절에서 재 봤다. 71489 에서 91.6%).

### 투창은 모델이 아니라 메시화가 지킨다

모델은 투창 자리에 **새 점을 0개** 만든다 (학습 완형이 전부 투창 있는 굽다리바리라
"굽다리에는 구멍이 있다"를 이미 배웠다). 문제는 메시화다 —
`(h, θ)` 격자는 점이 없으면 결손으로 보므로 그대로 두면 **패치가 덮어버린다.**
그래서 θ 점유의 **주기성**(n-fold)으로 갈라내 보호한다.

**다만 살이 깨진 창은 되돌린다.**

![깨진 살 복원](images/설명-깨진살복원.png)

투창은 단(tier)으로 나뉘고 각 단의 창은 크기가 고르다. 71489 는 정상 창 7개가
높이폭 0.08~0.11 인데 하나가 **0.20 · 683칸** 으로 위아래 단을 가로질렀다 —
그 사이 **가로살이 깨진 것**이다. 통째로 투창으로 보면 영영 안 복원되므로,
정상 창이 한 개도 안 걸치는 행만 결손으로 되돌린다 (71489 에서 184칸).
**그 높이의 다른 각도에는 살이 멀쩡하므로** 반지름·돌대·색을 회전 복사로 가져온다.

## 0. 왜 다시 보나

로드맵 §2.1 이 `PoinTr · AdaPoinTr` 를 제외로 올려뒀다. 근거는 팀의 두 반증인데
**둘 다 PoinTr 로 잰 것**이고 AdaPoinTr(2301.04545)는 확장판이다. 확장판의 개선점이
실패 원인과 겹치는지 **숫자로** 확인하고, 그 결과를 §2.1 에 박아 다시 안 꺼내게 만든다.

### 구조에서 나온 예측

AdaPoinTr 가 PoinTr 에서 바꾼 곳은 둘이다.

| 바꾼 곳 | 08-28 실패 원인에 닿나 |
| --- | --- |
| adaptive query generation (scoring 으로 top-M 선택) | **오히려 반대 방향.** 입력을 완형으로 읽으면 결손 쿼리 배정을 줄일 수 있다 |
| denoising 보조 과제 (학습 15배 가속) | 추론 경로에 없다. 학습 비용만 |

복원 헤드가 `P_i = f(H_i) + c_i` 라 **점은 프록시 중심 주변에만 생긴다.**
결손부에 중심이 안 찍히면 점이 나올 자리가 구조적으로 없다 — 08-28 의 "출력점 0점"이 이것이다.

**예측: 그대로 0점이 나온다.** 아래가 그 예측을 반증 가능하게 만든다.

## 1. 단계

```text
[0] 완형 확보                    ← 완료. 결론이 뒤집혔다 (§2)
[1] EA_028 에 AdaPoinTr 추론      ← 08-28 과 같은 입력·같은 지표. 변수 하나만 바꾼다
```

### 고친 것 둘

**1. 쐐기 중심을 데이터에서 고른다.** 처음엔 전 각도에서 균일하게 뽑았더니
`경주_고적_13472__rim0` 의 **결손률이 0.000** 이었다. 그 메시는 축 상단 띠가
**θ −141°~−46° 에만** 있어서(둘레 전체가 아니다) 쐐기가 빗나갔다.
이제 그 띠에 실제로 점이 있는 각도에서 중심을 고른다. 최소 결손률이 0.000 → 0.026 이 됐다.

> 결손이 0 인 쌍은 **`none` 인데 패턴 이름만 붙은 표본**이다. 라벨이 틀린 학습 표본은
> 표본이 하나 빠지는 것보다 나쁘다. 그래서 `MIN_REMOVED=0.02` 미만이면 최대 8회
> 다시 뽑고, 그래도 안 되면 버린다.

**2. 재현 가능한 난수.** 파이썬 `hash()` 는 문자열에 대해 **프로세스마다 값이 달라진다**
(PYTHONHASHSEED). 그대로 두면 돌릴 때마다 다른 데이터셋이 나온다. `sha1` 기반
`stable_seed()` 로 바꿨다.

`bottom` 의 결손 비율이 0.16~0.50 으로 낮게 나오는 개체가 있다. **고배는 굽다리가
가늘어서 높이의 30% 를 잘라도 표면적은 15% 밖에 안 준다.** 08-28 항아리의
"하부 몸통 전체 결실" 만큼 가혹하지 않다는 뜻이라, [2] 판정 때 감안할 것.

`align_damaged.py` 는 **잘록한 허리**를 축척 기준점으로 쓴다 — 굽다리의 굽은
원뿔이고 원뿔은 자기닮음이라 프로파일 RMSE 만으로는 축척이 안 잡힌다.
**굽 검사**(`foot_ok`)와 **정합 RMSE 게이트**(`--max-rmse`)로 상류가 무너진 점을 뺀다.

### `versions.py` — 결과물 버전 관리

이름에 설정을 욱여넣는 방식은 한계에 온다. 표 하나에 (번호, 폴더 꼬리표, 특징, 인자)를
적고 결과물은 `work/restored_adapointr/vNN_특징/` 밑에 `restored.glb` + `meta.json` 으로 간다.

```bash
$PY versions.py --list           # 무엇이 어떻게 다른지
$PY versions.py --build v15      # 그대로 다시 만든다
$PY versions.py --measure        # 전부 재서 버전표.csv
```

재는 것 여섯 가지 — **이면각**(국소 거칠기) · **θ 흔들림**(큰 파도) ·
**돌대**(가로 줄무늬가 이어졌나) · **색 국소 std**(무늬가 살아 있나) ·
**이음새 밝기차**(옆과 톤이 맞나) · **벽 두께**.

> 옛 버전은 **플래그로 고정한다.** 나중에 붙인 기능 때문에 옛 버전을 다시 빌드하면
> 그때 숫자가 안 나온다 (실제로 색 국소가 82% → 97% 로 달라졌다).
> `--no-tex-outer` 처럼 옛 동작을 남겨 **아무 줄이나 지금 다시 만들어도 같은 값**이 나오게 한다.

### `render_versions.py` — OpenGL 없이 그림 찍기

`Scene.save_image()` 는 pyglet 창을, pyrender 는 EGL 을 연다. TRELLIS venv 에 둘 다 없고
**그 venv 는 본 파이프라인이 쓰는 것이라 건드리지 않는다.**
numpy z-버퍼 + 평면음영이면 실제 재질 색과 음영 둘 다 나온다. 합성은 PIL 로 한다.

```bash
$PY render_versions.py --out images/비교.png --cols 3     "work/restored_adapointr/v22_투창교정/restored.glb:v22"
```
