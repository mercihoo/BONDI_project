환경은 **TRELLIS venv 하나**를 쓴다 (`gupdari-71489/실행-구조.md` §5 와 같다).

```bash
PY="<trellis2-stableprojectorz 의 code 폴더>/venv/Scripts/python.exe"
```

`torch 2.8.0+cu128` · `numpy` · `scipy` · `trimesh` · `pandas` 있음.
`laspy` · `open3d` · `sklearn` **없음** — 필요 없게 짰다 (§1.2).

### 1.1 데이터 흐름 — GLB 에서 모델 입력까지

**AdaPoinTr 는 메시를 못 먹는다. 점군만 먹는다.** 그래서 변환이 필요하고,
**그 변환은 `make_pairs.py` 가 이미 해뒀다.**

```text
trellis3d/*.glb              굽다리바리 42점 (TRELLIS 생성, 경계변 0)
      │
      │  ① 완형 필터  ← meta/artifacts.csv 대조
      │     plain · is_broken=False · mouth_cm 있음
      ▼
   완형 9점                   경주 2027·5756·5757·8478·887 · 대구대 1834·1835
      │                       신수 16068 · 증 873   ── 전부 굽다리바리다
      │  ② trimesh.sample_surface  120,000점 균일 샘플
      ▼                       (정점을 그냥 쓰면 밀도가 곡률에 쏠린다)
   조밀 점군
      │  ③ 회전축 = measure_glb.up_axis() → (h, θ, r)
      │  ④ 결손 마스크 4패턴 적용
      ▼
  partial / complete
      │  ⑤ 완형 기준 단위구 정규화 + 재샘플
      ▼
  work/pairs/*.npz            partial(2048,3) · complete(8192,3) · center · scale
      │
      │  ⑥ ← 여기부터가 아직 안 한 부분. 한 줄이다
      ▼
  torch.from_numpy(d["partial"]).unsqueeze(0).cuda()   → (1, 2048, 3)
```

**⑤의 정규화가 기여자 스크립트와 같은 방식이다** — `restore_standalone.py` 도
`centroid` 빼고 최대 노름으로 나눈다. 그래서 ⑥ 이 그냥 붙는다.

### 1.2 LAS 를 안 거친다

기여자 스크립트는 `load_las()` 로 시작하고 `laspy` · `open3d` 를 import 한다.
**둘 다 TRELLIS venv 에 없다.** 설치할 필요 없다 — 우리 입력은 이미 npz 라
`load_las` 를 건너뛰면 그 의존이 통째로 빠진다.

`restore_standalone.py` 에서 가져올 것은 **위쪽 순수 PyTorch 대체 블록 하나**다
(`_furthest_point_sample` · `_gather_operation` · `_three_nn` · `_three_interpolate` ·
`_grouping_operation` · `_ball_query`). 그게 §2 에서 필요하다던 바로 그 부분이고,
**AdaPoinTr 에 그대로 쓰인다.**

> 예외: **[1] EA_028 은 LAS 입력이다.** 그때만 `laspy` 가 필요하다.
> `pip install laspy` 한 줄이고, `open3d` 는 그때도 필요 없다(기여자 스크립트가
> 시각화용으로 import 만 해둔 것).

## 2. 막힌 것 하나 — 그리고 우회로

**[1][2] 둘 다 AdaPoinTr 추론이 돌아야 한다.** 필요한 게 셋이다.

| # | 필요한 것 | 어디서 | 상태 |
| ---: | --- | --- | --- |
| 1 | AdaPoinTr 코드 | `github.com/yuxumin/PoinTr` | ✅ `vendor/PoinTr/` |
| 2 | ShapeNet-55 사전학습 가중치 | Tsinghua Cloud | ✅ `ckpts/AdaPoinTr_s55.pth` (389MB · 32.5M 파라미터) |
| 3 | **CUDA 확장 없이 도는 추론 경로** | 기여자 `restore_standalone.py` | ✅ 확보 |
| 4 | 판정 스크립트 | 직접 | ✅ `eval_completion.py` (자체 검증 완료 §4) |

**막힌 것이 없다. 남은 건 ③ 을 AdaPoinTr 로 갈아끼우고 돌리는 것뿐이다.**

`ckpts/AdaPoinTr_s55.pth` 의 state dict 키에 `base_model.` 접두어가 있다.
기여자 스크립트가 `module.` 만 떼므로 **접두어 처리를 한 줄 더 봐야 한다.**

```python
raw = ckpt.get('base_model', ckpt)
sd = {k.replace('module.', '', 1): v for k, v in raw.items()}
```

`ckpt['base_model']` 로 이미 한 겹 들어갔는데 그 **안의 키도 `base_model.` 로 시작**한다
— 실제로 확인한 값이다. `strict=False` 라 조용히 다 missing 이 될 수 있으니
`load_state_dict` 반환의 `missing_keys` 개수를 반드시 찍어볼 것.

### 2.1 3번은 받았다 — 예상대로였다

`Downloads/restore_standalone.py` · `restore_ea028.py`.
위쪽에 `pointnet2_ops` 를 순수 PyTorch 로 갈아끼운 블록이 통째로 들어 있다.

```python
_furthest_point_sample   # 반복 최원점. (B,N,3) → (B,npoint)
_gather_operation        # torch.gather
_three_nn                # torch.cdist + topk
_three_interpolate
_grouping_operation
_ball_query              # cdist + topk + radius 마스크
```

`models` 패키지 import 전에 `sys.modules` 에 등록하는 방식이라 **모델 코드를 안 고친다.**
AdaPoinTr 도 같은 연산을 쓰므로 그대로 붙는다.

**PoinTr → AdaPoinTr 로 바꿀 곳은 셋뿐이다.**

| | `restore_standalone.py` 현재 | 바꿀 것 |
| --- | --- | --- |
| 모델 | `from models.PoinTr import PoinTr` | `from models.AdaPoinTr import AdaPoinTr` |
| 설정 | `cfgs/ShapeNet55_models/PoinTr.yaml` | `cfgs/ShapeNet55_models/AdaPoinTr.yaml` |
| 가중치 | `pretrained/pointr_shapenet.pth` | AdaPoinTr ShapeNet-55 체크포인트 |

denoising 은 학습 전용이라 추론 호출부(`coarse, fine = model(x)`)는 그대로다.
다만 geometry-aware 블록의 kNN 에서도 대체가 먹는지는 **돌려봐야 안다** — 여기가 유일한 미지수다.

### 2.2 못 받으면 — 직접 만든다. 반나절이면 된다

PoinTr 저장소의 CUDA 확장 중 **AdaPoinTr 추론에 실제로 필요한 건 둘뿐**이다.

| 확장 | 쓰나 | 순수 PyTorch 대체 |
| --- | --- | --- |
| `pointnet2_ops` FPS | **예** | 반복 최원점 선택. N=2048·M=512 라 순진한 구현으로 충분 |
| `pointnet2_ops` kNN/grouping | **예** | `torch.cdist` + `topk`. 2048×2048 행렬이라 부담 없음 |
| `chamfer_dist` | 아니오 | 평가는 우리가 `scipy.spatial.cKDTree` 로 한다 |
| `gridding` · `cubic_feature_sampling` · `emd` | 아니오 | GRNet 등 다른 모델용 |

**이 경로가 살아 있어서 2.1 이 막혀도 [1][2] 는 진행된다.** 블로커가 아니라 지연이다.

## 4. 판정 스크립트 — `eval_completion.py` ✅

[1][2] 양쪽을 같은 축으로 잰다. `scipy.spatial.cKDTree` 로 전부 된다.

| 지표 | 정의 | 기준선 |
| --- | --- | --- |
| **보충점** | 출력점 중 입력 `partial` 에서 τ 넘게 떨어진 것 = 모델이 새로 만든 점 | **0** (08-28) |
| **유효 보충점** | 그 보충점 중 **결실 영역 정답**에 δ 이내로 붙은 것 | — |
| **결실 커버리지 순증** | 결실 정답점 중 출력이 δ 이내인 비율 — **바닥값을 뺀 것** = **재현율** | 0 ~ 1 |
| **정밀도** | 보충점 중 정답 δ 이내인 비율. **나중에 더했다** (§5.14) | 무작위 산포 **0.03** |
| **F순증** | 위 둘의 조화평균 | — |
| 잔존부 오차 | 출력 ↔ `partial` 최근접 거리 중앙값 | 3.5mm (08-28) |
| 출력 점간격 | 최근접 이웃 거리 중앙값 | ~12mm (원본 1.63mm) |
| 정답 대비 CD | 출력 ↔ `complete` 양방향 | ([2] 에서만) |

τ·δ 는 **입력 점간격의 3배**로 잡는다. 절대값을 박으면 유물 크기마다 뜻이 달라진다.
결실 영역은 `complete_removed` 마스크를 쓴다 — 거리로 역추정하지 않는다.

> **정밀도가 처음에 없었다.** 커버리지만 보면 **점을 사방에 뿌릴수록 올라간다** —
> 무작위 산포 대조군이 `side` 에서 순증 **1.000** 을 받는다 (정밀도 0.042).
> `n_new_valid` 를 이미 세고 있었는데 비율로 안 쓰고 있었다 (§5.14).

### 4.1 판정기를 먼저 검증했다

모델 없이 **정답을 아는 두 극단**을 넣어봤다. `--self-test`

| 넣은 것 | 뜻 | bottom 유효보충점 | 커버리지 | **바닥값** | **순증** |
| --- | --- | ---: | ---: | ---: | ---: |
| `partial` | 아무것도 안 메운 모델 | 0 | 0.081 | 0.081 | **0.000** |
| `complete` | 완벽히 메운 모델 | **2,315** | 1.000 | 0.081 | **1.000** |

> ### 바닥값을 왜 빼나 — 여기서 함정을 하나 잡았다
>
> **아무것도 안 메운 모델도 커버리지가 0 이 아니다.** `rim` 0.345 · `side` 0.367.
> 결손 띠가 얇으면 정답점이 남은 표면 δ 안에 들어가기 때문이다.
> 빼지 않으면 **"아무것도 안 하고 35% 메웠다"** 가 된다.
>
> `cover_gain = (cover − floor) / (1 − floor)` 로 0~1 에 정규화한다.

**게이트가 이 실측으로 보정됐다** — 완벽한 모델의 `bottom` 유효보충점이 2,315 이므로
통과선 1,000 은 **완벽 대비 43%** 다. 자의적인 숫자가 아니다.

`none` 에 완벽한 모델을 넣어도 보충점이 3 나온다 (재샘플링 잡음).
통과선 200 은 그 잡음의 60배라 여유가 넉넉하다.

- **①이 미달** (0~수십 점) → **반증 확정.** §7 로 간다

> **결과 — 둘 다 통과했고 [3] 으로 갔다.** 다만 게이트를 통과시킨 것은
> 모델이 아니라 **평가를 고친 것**이었다 (§4.5 정규화 누출).
> 지금 최종 성적은 테스트 세트 깊은 결손(0.50~0.65)에서 **F순증 0.918** 이다
> ([결과.md](결과.md) §5.15).

### G-B. 닫을 때 하는 일

로드맵 §2.1 의 `PoinTr · AdaPoinTr` 행에 근거를 박는다. 지금 그 행은 AdaPoinTr 까지
묶어놓고 증거는 PoinTr 것만 달려 있어서, **다음에 누가 "확장판은 다르지 않나"로
또 꺼낸다.** 이번 숫자가 그걸 막는다.

### 7.2 A 를 먼저 하는 이유

71489 에 넣었더니 보충점 20개였는데, **원인이 "모델이 못 한다"가 아니다.**
입력이 TRELLIS 출력이라 **경계변 0 의 닫힌 껍질**이고, **TRELLIS 가 아가리를 이미 메워놨다.**
모델 입장에서 구멍이 없으니 메울 것이 없다 — 맞는 판단이다.

[2] 의 `rim` 은 순증 **0.961** 로 잘 됐는데, 그 입력은 **내가 실제로 떼어낸** 것이라 구멍이 있었다.

> **우리에겐 결손 마스크가 있다** (영역 축 — 크기 문턱 + n-fold).
> 그걸로 껍질을 잘라 **진짜 구멍이 있는 부분 점군**을 만들어 넣으면
> [2] 의 `rim` 조건이 된다. **그때 되는지가 진짜 질문이다.**

B(파인튜닝)보다 A 가 먼저인 이유: 하루가 아니라 두세 시간이고, **A 가 되면 B 가 불필요하고
A 가 안 되면 형상 9개짜리 B 로는 더 안 된다.**
