## 3. 어떻게 쓰나 — 결손 6패턴

완형 하나에서 네 가지로 깬다. **패턴은 08-28 실패를 겨냥해 골랐다.**

![결손 패턴](images/데이터-결손-패턴.png)

| 패턴 | 무엇 | 왜 이걸 넣나 | 결손률 |
| --- | --- | --- | ---: |
| `none` | 결손 없음 | **빠지면 모델이 "입력은 항상 부족하다"를 배워 멀쩡한 유물에 살을 붙인다** (로드맵 §1.1 의 과채움). 판정 ②를 재는 유일한 수단 | 0% |
| `bottom` | 하부 결실 | **08-28 에서 출력점 0점이 나온 바로 그 형태** | 18~46% |
| `rim` | 구연부 결손 | **71489 가 이 상태다** (둘레 전체 톱니) | 3~18% |
| `side` | 측면 파단 | 일반적인 파손 | 4~21% |
| **`ragged`** | **둘레 전체를 물결 높이로** | **71489 와 같은 양상.** `rim` 은 한 구간만 떼는데 실제는 둘레 전체가 톱니다 | 6~25% |
| **`slant`** | **비스듬한 평면 — 한쪽만 남는다** | **깊은 결손을 못 메우던 것을 이게 풀었다** (§5.11). 굽다리는 남긴다 | 33~77% |

**착수 때 4패턴 × 2회 = 72쌍**이었다. 지금은 **6패턴 × 20회**다.

| | 착수 | **지금** |
| --- | ---: | ---: |
| 패턴 | 4 | **6** |
| 반복 | 2 | **20** |
| 형상 | 9 | **19** |
| 쌍 | 72 | **2,280** |

> **`slant` 가 v3 의 핵심이다.** 깊은 결손(0.50~0.65)에서
> F순증이 **0.229(v1) → 0.625(v2) → 0.918(v3)** 로 올랐다.

> **감안할 것.** `bottom` 결손률이 18% 까지 낮게 나오는 개체가 있다.
> **고배는 굽다리가 가늘어서 높이의 30% 를 잘라도 표면적은 18% 밖에 안 준다.**
> 08-28 항아리의 "하부 몸통 전체 결실" 만큼 가혹하지 않다 — 판정 때 감안할 것.

## 4. GLB 에서 모델 입력까지

**AdaPoinTr 는 메시를 못 먹는다. 점군만 먹는다.** 그 변환이 `make_pairs.py` 다.

```text
trellis3d/*.glb          굽다리바리 43점 (TRELLIS 생성, 경계변 0 닫힌 껍질)
      │  ① 완형 필터 ← meta/artifacts.csv 조건 셋 (§2)
      ▼
   완형 9점
      │  ② trimesh.sample_surface  12만점 균일 샘플
      │     정점을 그냥 쓰면 밀도가 곡률에 쏠린다
      │  ③ 회전축 ← measure_glb.up_axis()  → (h, θ, r)
      │  ④ 결손 4패턴 적용 → keep 마스크
      │  ⑤ 완형 기준 단위구 정규화 + 재샘플
      ▼
  work/pairs/*.npz
      │  ⑥ torch.from_numpy(d["partial"]).unsqueeze(0).cuda()   ← 남은 건 이 한 줄
      ▼
   AdaPoinTr
```

**⑤의 정규화가 기여자 `restore_standalone.py` 와 같은 방식이다** —
centroid 빼고 최대 노름으로 나눈다. 그래서 ⑥ 이 그냥 붙는다.

**회전축은 직접 구현하지 않았다.** `gupdari-shape-prior/measure_glb.up_axis()` 를 불러 쓴다 —
거기서 두 번 틀린 것(`argmax(bbox)` · 축길이 동점)을 또 틀리지 않으려고.

### npz 규격

| 키 | 모양 | 뜻 |
| --- | --- | --- |
| `partial` | (2048, 3) f32 | **모델 입력.** 깨진 점군 |
| `complete` | (8192, 3) f32 | **정답 완형** |
| `complete_removed` | (8192,) bool | **떼어낸 영역의 정답점 = 판정의 "결실 영역"** |
| `center` · `scale` | (3,) · () f64 | 원좌표 복원 |
| `up_axis` · `pattern` | () | 회전축 인덱스 · 패턴 이름 |

> **`complete_removed` 를 왜 저장하나.** 처음엔 "partial 에서 먼 complete 점"으로
> 역추정했다. **틀렸다** — partial 이 2048점이라 성긴 곳까지 결손으로 잡혀
> **결손 0% 인 `none` 에도 빨간 점이 흩어졌다.** 생성 시점에 마스크를 들고 있으면 정확하다.
> 판정 스크립트도 이 마스크로 "결실부 출력점 수"를 센다.

## 5. 재현

```bash
PY="<trellis2-stableprojectorz 의 code 폴더>/venv/Scripts/python.exe"

# AI-Hub 전수 측정 (62초)
$PY scan_dataset.py

# 학습·검증 쌍 — 완형 필터가 기본으로 켜져 있다 (16형상)
$PY make_pairs.py --per-pattern 20                    # 1,920쌍

# 테스트 쌍 — 유물을 지정한다. 완형 필터를 건너뛴다
$PY make_pairs.py --only "경주_4614,경주_4614_2,경주_8480"        --per-pattern 20 --pairs-out work/pairs_test --seed 777

# 패턴만 골라 빨리 보고 싶을 때
$PY make_pairs.py --patterns none,bottom

# 그림 (matplotlib 이 여기에만 있다)
PY2="../shape-prior/.venv/Scripts/python.exe"
$PY2 make_figures.py
```

난수는 `sha1` 기반이라 **몇 번을 돌려도 같은 쌍이 나온다**
(파이썬 `hash()` 는 문자열에 대해 프로세스마다 달라져서 못 쓴다).

**테스트 쌍은 씨앗을 777 로 따로 준다.** 학습 쌍(0)과 같은 씨앗이면
같은 자리로 깎여 비교가 흐려진다.

| **전부 굽다리바리다** | 그래서 **형상 홀드아웃이 사실상 홀드아웃이 아니다** — *"못 본 형상"* 이 *"못 본 굽다리바리"* 일 뿐이다. 기종 밖(`EA_028` 항아리)은 출력점 **0개**로 실패했다 (§3) |

| **합성 결손 ≠ 실제 파단** | 매끈한 절단면이다. 실제 파단은 두께·요철이 있다 |
