## 1. 단계별

### ① 사진 → 관측 3D (TRELLIS)

| | |
| --- | --- |
| 스크립트 | `gupdari-shape-prior/run_trellis_batch.py` |
| 모델 | TRELLIS.2-4B |
| 설정 | `--decimation 200000 --texsize 1024` |
| 시간 | 유물당 **약 9.5분** (RTX 4070 Laptop 8GB) |

**실행마다 결과가 다르다.** 같은 사진을 두 번 태워 쟀다 —
프로파일 RMSE 중앙 **0.0049**, 최대 0.0137, 축척 0.998~1.006.
이 값이 이후 모든 비교의 **잡음 바닥**이다.

### ② 관측 3D 의 성질 — 이걸 알아야 나머지가 이해된다

| | 값 | 왜 중요한가 |
| --- | --- | --- |
| 정점 · 면 | 94,877 · 149,150 | 점 간격 0.71mm |
| watertight | **아니다** | 파단면이 열려 있다 |
| 용접 후 경계변 | **38,816** | 법선으로 벽을 가르면 여기서 오염된다 |
| 구조 | **두께 있는 껍질** | 한 `(h,θ)` 칸에 **바깥벽과 안쪽벽이 같이** 들어간다 |
| 벽 두께 | 중앙 **5.9mm** (아가리 2.4 ~ 굽 이음 22) | 높이별 3배 넘게 변한다 |

> **이 폴더에서 생긴 버그의 절반이 "한 칸에 벽이 둘"에서 나왔다.**
> 칸 중앙값은 두 벽의 한가운데에 떨어지고, 분위수 폭은 벽의 굽음을 같이 재고,
> 텍스처 표본에는 그늘진 안쪽벽이 섞인다. 새 기능을 붙일 때 항상 먼저 확인할 것.

### ③ 학습 쌍 — 완형 3D 를 3D 에서 깎는다

```bash
$PY make_pairs.py --per-pattern 20
```

| | |
| --- | --- |
| 완형 | **16점** — 메타 기준 9점 + 실측 결손률·사진으로 손수 고른 7점 (`plain` 12 · **`handled` 3** · `dish` 1) |

### 분할 — **형상 단위**

쌍 단위로 나누면 **같은 유물이 학습과 평가에 같이 들어간다.** 의미가 없다.

| | 형상 | 쌍 | 무엇에 쓰나 |
| --- | ---: | ---: | --- |
| **train** | 14 | 1,680 | 가중치 학습 |
| **val** | 2 | 240 | **에폭 선택** (`경주_887` · `대구대_1834`) |
| **test** | 3 | 360 | 보고용. `경주_4614` · `경주_4614_2` · `경주_8480` |
| 합 | **19** | **2,280** | 73.7 / 10.5 / 15.8% |

> **test 는 나중에 뺐다.** 처음에는 val 로 에폭을 고르고 **그 val 로 성능을 보고**하고
> 있었다. 뒤늦게 알아차려 3형상을 더 빼 다시 쟀더니 **5%p 낙관적**이었다
> (결과.md §5.15). 그래서 val 이 test 보다 작다 — 설계된 비율이 아니다.
>
> 테스트 3형상은 **학습에도 에폭 선택에도 안 썼다.** 다만 남은 후보 중
> **가장 온전한 것**으로 골랐으므로(결손 0.1~2.2%) 정답이 학습 완형(0.1~14%)보다
> 깨끗하다 — 그만큼 **실제보다 쉬울 수 있다.**
> 그리고 **손잡이 기종이 없다** (후보의 `handled` 하나가 굽이 깨져 있었다).

패턴 여섯:

| 패턴 | 무엇을 떼나 | 왜 |
| --- | --- | --- |
| `none` | 아무것도 | **과채움 대조군** — 완형을 넣어도 안 늘려야 한다 |
| `bottom` | 바닥 쪽 | 굽 결실 |
| `rim` | 아가리 한 구간 | 쐐기꼴 결손 |
| `side` | 옆면 한 덩어리 | 몸통 구멍 |
| `ragged` | **둘레 전체를 물결 높이로** | **71489 와 같은 양상** (결손 2.6~27.5%) |
| **`slant`** | **비스듬한 평면으로 — 한쪽만 남는다** | 몸통이 날아간 실제 파손 (결손 **34.6~70.7%**). 굽다리는 남긴다 |

**꼭 지킬 것 둘**

- 결손 마스크는 **깎을 때 같이 저장한다.** 거리로 나중에 추정하면 `none` 쌍에서도
  가짜 결손이 생긴다.
- 씨앗은 sha1 기반 `stable_seed()`. 파이썬 `hash()` 는 프로세스마다 달라 재현이 안 된다.

### ⑤ 추론 — **AI 는 점을 어떻게 찍나**

> 발표에서 가장 많이 받는 질문이다. *"AI 가 형상을 만든다"* 는 말이 뭉뚱그려져 있는데,
> 실제로 일어나는 일은 **점 8,192개의 좌표를 예측하는 것**이고 그게 전부다.
> 면(face)도, 두께도, 색도 모델이 만들지 않는다 — 그건 ⑥ 에서 우리가 만든다.

```
입력  점 2,048개 (x,y,z)          ← 관측 표면에서 FPS 로 고르게 뽑은 것
출력  점 8,192개 (x,y,z)          ← 완형이라고 모델이 생각하는 것
```

**① 점을 묶어 토큰으로** — 트랜스포머는 토큰 열을 먹는데 점군은 순서가 없다.
FPS 로 중심점 512개를 고르고 그 주변을 경량 DGCNN 으로 훑어 **국소 패치 하나 = 토큰 하나**로 만든다.
그래서 이 모델이 보는 최소 단위는 점이 아니라 **패치**다.

**② 인코더** — self-attention 옆에 kNN 국소 집계를 나란히 붙인다.
전역 attention 만으로는 면의 굴곡 같은 국소 기하를 놓치기 때문이다.

**③ 쿼리 생성 — 여기가 핵심이다.** 디코더가 채워 넣을 *"빈칸 토큰"* 을 만든다.
AdaPoinTr 는 이것을 **입력에서 온 것 `Q_I` 와 새로 만든 것 `Q_O` 를 합쳐** 쓴다.
결손부를 담당하는 것은 `Q_O` 다.

**④ 복원 헤드** — 토큰마다 중심 `cᵢ` 를 잡고 그 주위에 점을 펼친다.

```
Pᵢ = f(Hᵢ) + cᵢ        ← FoldingNet 형. 중심에서 상대 좌표를 펴서 더한다
```

> **이 식이 이 파이프라인의 한계를 정한다.** 점은 **중심 `cᵢ` 주위에만** 생긴다.
> 결손부에 프록시 중심이 안 찍히면 **거기엔 점이 생길 자리가 없다.**
> 실제로 `EA_028`(바닥 없는 항아리)에서 결실부 출력점이 **0개**였던 이유가 이것이다.

**⑤ 출력은 정렬돼 있지 않다.** 8,192개의 점은 순서도, 면 연결도, 안팎 구분도 없다.
게다가 **입력과 겹치는 점이 대부분**이다 — 새로 만든 점은 5,185개 중 일부고,
나머지는 입력을 그대로 베낀 것이다. 그래서 ⑥ 에서 **무엇이 새것인지부터 가른다.**

### ⑤b 회전 TTA

### ⑥ 메시화 — 2노드 분리

```bash
$PY make_mesh_2node.py --src work/pred_71489_A_normal_tta8.npz \
  --nh 144 --nt 216 \
  --outer-shift 1.0 --axisym 0.85 --axisym-ramp 6 \
  --r-smooth 1.2 --ridge --ridge-gain 0.25 \
  --dilate 3 --seam-tuck 0.5 --seam-tuck-ramp 3 \
  --thickness --smooth 20 --edge-rings 3 --mask-smooth 2.5 \
  --rot-texture --tex-samples 1500000 --tex-clean 0.8 --tex-blend 40 \
  --name v22
```

**관측부는 한 점도 안 건드린다.** 모델이 기여하는 것은 결손부뿐이라,
재샘플링하면 투창과 해상도만 잃는다. v32 의 `region_carried` / `region_filled` 와
같은 구조다 (`NFR-ETH-003`).

```
region_observed   원본 A_normal.glb **무수정**  V=94,877  F=149,150
region_ai         결손 칸만 격자로 메시화       V=21,116  F= 52,626
```

#### 처리 순서 — 순서가 곧 설계다

| # | 단계 | 인자 | 하는 일 |
| --- | --- | --- | --- |
| 0a | **밀도 거르기** | `--density-keep 0.70` `--density-bands 24` | 새 점 중 **빽빽한 심만**. 임계는 **높이 띠마다** — 전역 하나면 아가리 연장이 5%만 남는다 |
| 0b | **면 퍼짐 게이트** | `--max-scatter 0.07` | 걷어내고도 구름이면 **메시를 안 만든다** |
| 1 | 결손 칸 판정 | — | 조밀 점군이 빈 칸 중 **투창이 아닌 것** |
| 2 | 투창 보존 | `--openwork-hmax 0.55` | θ-점유 푸리에로 **n-fold** 판정. 굽다리 위는 판정 안 함 |
| 2b | **깨진 살 복원** | `--fix-strut` | 비정상적으로 큰 창은 살이 깨진 것 — 그 행만 결손으로 되돌린다 |
| 3 | 팽창 · 평활 · **닫기** | `--dilate 3` `--mask-smooth 2.5` `--mask-close 2` `--min-island 40` | 격자 계단을 깎고 잔구멍을 메운다 |
| 3b | **조각 날리기** | `--drop-loose 6` `--min-piece 300` | 관측에 안 닿거나 300면 미만인 부스러기를 버린다 |
| 4 | **바깥벽 정렬** | `--outer-shift 1.0` `--outer-cov-lo 0.30` | 칸 중앙값은 **두 벽의 한가운데**다. 행마다 관측 바깥면에 맞추되, **θ 점유가 낮으면 모델**을 쓴다 |
| 5 | **회전체 되돌림** | `--axisym 0.85` `--axisym-ramp 6` | θ 변동은 정보가 아니라 잡음. 이음새에서 멀수록 강하게 |
| 6 | 격자 평활 | `--r-smooth 1.2` | 기본면을 먼저 매끄럽게 |
| 7 | **돌대 이식** | `--ridge-gain 0.25` | 관측 `r(h)` 의 **대역통과**만 얹는다 |
| 8 | 벽 두께 | `--thickness` | **단면의 빈 틈**으로 재고 안쪽벽 생성 |
| 9 | 이음새 tuck | `--seam-tuck 0.5` | 관측 껍질 **밑으로** 깔아 틈을 막는다 |
| 10 | 테두리 평활 | `--smooth 20` `--edge-rings 3` | 이음새는 고정, 자유 테두리만 |
| 11 | 텍스처 | `--rot-texture` 외 | **거울 타일링** + 밝기 이음 |

**4~7 의 순서가 중요하다.** 먼저 면을 매끄럽게 만들고 그 위에 돌대를 얹어야
두 손잡이(`--r-smooth`, `--ridge-gain`)가 독립이 된다. 반대로 하면 평활이 돌대를 같이 깎는다.

**방향도 나눈다** — θ 방향(각도별 차이)은 근거가 없으니 지우고,
h 방향(돌대)은 관측에서 읽은 실제 정보이니 남긴다.

#### 텍스처 — 회전 복사

`(h, θ)` 격자가 곧 UV 다 (`u = θ/2π`, `v = 정규화 h`). 따로 펼칠 필요가 없다.

| # | 단계 | 왜 |
| --- | --- | --- |
| 1 | **원본 텍셀 직접 표집** | 정점색으로 구우면 1024² 가 정점 94,877 로 줄어 디테일이 죽는다 |
| 2 | **바깥면 표본만** | 안쪽벽이 **표본의 52%** 이고 그늘져서 어둡다 |
| 3 | 관측 속 빈 텍셀 메움 | 정규화 합성곱. 큰 결손부까지 안 번지게 sigma 작게 |
| 4 | 산탄잡음 정리 (`--tex-clean`) | 텍셀당 표본이 3개라 색이 튄다. **관측 안에서만** |
| 5 | **거울 타일링** | 관측 띠를 둘레에 붙인다. 한 주기를 `seg + seg[::-1]` 로 잡아 경계가 안 끊긴다 |
| 6 | 밝기 이음 (`--tex-blend`) | 얼룩이 회전대칭이 아니라 톤이 어긋난다. 무늬는 두고 **밝기만** 잇는다 |

> **중앙값을 쓰면 안 된다.** 도너 k개의 중앙값은 튀는 값도 지우지만 **무늬도 지운다** —
> 결손 호에서 먼 텍셀도 같은 가장자리 k개만 보게 돼 호 전체가 한 색으로 눕는다.

### ⑦ 버전 등록과 측정

```bash
$PY versions.py --build v22     # 그대로 다시 만든다
$PY versions.py --measure       # 전부 재서 버전표.csv
```

결과물은 `work/restored_adapointr/vNN_특징/restored.glb` + `meta.json`(인자·빌드 로그).

**옛 버전은 플래그로 고정한다.** 나중에 붙인 기능 때문에 옛 버전을 다시 빌드하면
그때 숫자가 안 나온다 (실제로 색 국소가 82% → 97% 로 달라졌다).

## 2.5 모델 자체는 어떻게 재나

위 §2 는 **결과물**을 잰다. 모델이 얼마나 잘 메우는지는 다른 잣대다.

```bash
$PY eval_completion.py --self-test                     # 판정기 검증
$PY eval_all_models.py --pairs=work/pairs_test \
     base=… v1=… v2=… v3=…                              # 여러 가중치를 한 표로
```

| 지표 | 묻는 것 |
| --- | --- |
| **재현율** (커버리지) | 결손 정답점 중 예측이 δ 안에 있는 비율 |
| 바닥값 | 아무것도 안 메운 모델도 공짜로 받는 몫 |
| **순증** | `(재현율 − 바닥값) / (1 − 바닥값)` → 0~1 |
| **정밀도** | 보충점 중 정답 δ 안에 있는 비율 |
| **F생 / F순증** | 위 둘의 조화평균. 바닥값을 빼기 전 / 후 |
| 과채움 | `none` 쌍(완형)에 만드는 점 수. 0 에 가까워야 한다 |

**δ = 정답 점간격 × 3.**

### 셋을 반드시 지킨다

**① 자기 정규화.** `make_pairs` 는 `partial` 을 `complete` 의 자로 저장한다.
그대로 넣으면 **모델이 원래 크기를 액자에서 읽는다** (§4.5).
`run_adapointr.py --self-normalize` 가 **기본 꺼짐**이라 안 걸면 조용히 누출된다.

| `base` (파인튜닝 안 함) | 누출된 자 | **자기 정규화** |
| --- | ---: | ---: |
| `rim` 순증 | 1.000 | **0.257** |
| `slant` 순증 | 0.944 | **0.036** |

**② 재현율만 보지 않는다.** 무작위로 점을 뿌리는 대조군이 `side` 에서
순증 **1.000** 을 받는다 (정밀도 0.042). 정밀도와 **같이** 본다.

**③ 깊이별로 본다.** 쌍의 절반이 결손률 0.20 미만이라 전체 중앙값은
**쉬운 구간에 앉는다.** 그렇게 보면 v1 이 0.902 인데 깊은 결손에서는 **0.229** 다.

### 판정기를 정답으로 검증한다

`--self-test` 가 대조군 셋을 넣어 본다.

| `pred` 에 무엇을 넣나 | 순증 | 정밀도 |
| --- | ---: | ---: |
| 완벽 (`complete`) | **1.000** | **0.997~1.000** |
| 아무것도 안 함 (`partial`) | **0.000** | — |
| 무작위 산포 | 0.017~1.000 | **0.002~0.127** |

### 지금 성적 — 테스트 세트 360쌍

| 결손 깊이 | 쌍 | 사전학습 | v1 | v2 | **v3** | v3−v2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.00~0.20 | 136 | 0.641 | 0.899 | 0.836 | 0.895 | +0.060 |
| 0.20~0.35 | 34 | 0.082 | 0.702 | 0.702 | **0.867** | +0.165 |
| **0.35~0.50** (71489 수준) | 51 | 0.082 | 0.438 | 0.586 | **0.936** | **+0.350** |
| 0.50~0.65 | 21 | 0.026 | 0.229 | 0.625 | **0.918** | +0.292 |

**71489 는 아가리에서 아래로 높이의 40~50% 가 손상돼 있다** —
h 0.6 위로 결손이 40~81% 다. 위 표의 `0.35~0.50` 구간이 그 수준이다.

**v3 의 이득은 전부 깊은 쪽에 있다.** 얕은 결손에서는 v1 과 사실상 동률이다.

## 2.6 어디까지가 학습이고 어디부터가 규칙인가

**발표에서 가장 자주 오해받는 곳이다.** 세 층으로 갈라 둔다.

| | 무엇 | 누가 정하나 |
| --- | --- | --- |
| **① 학습된 것** | AdaPoinTr 가중치 (`.pth`) | **데이터가 정한다.** 75분 × 3회 |
| **② 설계한 규칙** | `(h,θ)` 격자 · *"점 없는 칸 = 결손"* · 투창 n-fold · 2노드 분리 | 내가 설계. **학습 안 한다** |
| **③ 고른 임계값** | 아래 표 | 내가 고름. **숫자를 보고** |

> **③을 바꿔도 `.pth` 는 손대지 않는다.** 그래서 이것은 **하이퍼파라미터 조정이 아니다** —
> 학습 하이퍼파라미터(`lr` · 배치 · 에폭 · 채택 기준)는 §④ 에 따로 있고,
> 그쪽을 바꾸면 가중치가 바뀐다. 이쪽은 **후처리 임계값**이라 부르는 것이 맞다.

### ③ — 값과 그 근거

| 임계값 | v22 | 왜 그 값인가 |
| --- | ---: | --- |
| **면 퍼짐 거부** | **0.07** | 실측값 **사이가 비어 있다** (아래) |
| **밀도 거르기** | 상위 **70%** | 퍼짐이 고적_13472 0.0765 → **0.0514** (임계 아래로), 71489 0.0511 → 0.0383 |
| 밀도 띠 수 | 24 | 전역 임계 하나면 **아가리 연장이 5% 만 살아남는다** (311점 → 17점) |
| **회전체 블렌드** | **0.85** | 0 이면 이면각이 **28°** 까지 뛴다 (관측 6.0°). 1 이면 이음새에 턱이 생긴다 |
| 바깥벽 정렬 | 1.0 | 안 하면 복원면이 관측면보다 **중앙 3.8mm · 위쪽 8mm** 안으로 파묻힌다 |
| **투창 높이 제한** | h < **0.55** | 굽/바리 이음이 h 0.4~0.5 다. 그 위는 몸통이라 투창일 수 없다 |
| 깨진 살 비율 | 1.6배 | 정상 창 높이폭 0.08~0.11 인데 하나가 **0.20** 이었다 |
| 조각 최소 면수 | 300 | 거리만으로는 못 거른다 — 부스러기가 굽다리 옆에 붙어 있다 |
| 이음새 팽창 | 3칸 | 패치 테두리와 관측 가장자리가 **중앙 2.5mm · 최대 5.1mm** 어긋난다 |

### 면 퍼짐 0.07 — **빈 구간에서 잘랐다**

```
정상   71489        0.051 ─┐
                           ├─  여기가 비어 있다  →  0.07 로 자름
구름   고적_13472   0.077 ─┘ ~ 0.186
```

`경주_고적_13472` 가 파단선을 둘레로 돌려 **없는 넓은 챙**을 만든 것이 계기다.
점 수로는 못 가른다 — **그 유물이 점을 가장 많이 만든 축**이었다.

### 한계 — 임계값을 유물 2점으로 골랐다

모델 쪽은 train / val / test 를 나눴는데 **메시화 쪽은 안 나눴다.**
위 임계값은 `71489` 와 `경주_고적_13472` 를 보고 정했고, **그 둘이 곧 시연 대상**이다.
후처리판 과적합이다.

**다만 나중에 확인은 됐다.** 2026-09-18 에 처음 보는 유물 셋에 돌렸더니:

| | 면 퍼짐 | 게이트 |

## 5. 곁줄기 — sim-to-real 검증 **(중단)**

> **2026-09-17 에 멈췄다.** 만들어 둔 얕은 세트가 6형상 200쌍뿐이라
> 16형상 1,920쌍(v3)과 비교가 성립하지 않고, §5.11 이 다른 길로 같은 증상을 풀었다
> (`slant` 패턴 → 깊은 결손 0.510 → 0.985).
> **가설이 기각된 것은 아니다 — 상류 경로 차이는 여전히 미검증이다.**
> 다시 열려면 완형 사진을 더 모아 얕은 세트를 16형상 규모로 키우는 것이 먼저다.
> 만든 자료(`work/pairs_photo/` `trellis3d_damaged/` `photo_damaged/` `aligned/`)는
> 남겨 뒀다 — TRELLIS 재실행이 유물당 9.5분이다. 아래는 그때 한 방법의 기록이다.

합성 데이터에서는 되는데(깊이 0.40~0.50 에서 0.913) 실제 71489 에서는 그만큼 안 나온다.
후보 넷 중 셋을 실험으로 기각했고 **상류 경로 차이**만 남았다 —
학습 완형은 *온전한* 사진의 TRELLIS, 71489 는 *깨진* 사진의 TRELLIS다.

```bash
$PY make_photo_damage.py --base 0.35 --run-trellis   # 사진을 먼저 깬다
$PY align_damaged.py                                  # 원본 3D 와 같은 자에 올린다
```
