## 2. 내가 틀린 것

[모델-AdaPoinTr.md](모델-AdaPoinTr.md) §6 에 이렇게 적었다.

> *"예측: 그대로 0점이 나온다."*

근거는 구조였다 — 복원 헤드가 `Pᵢ = f(Hᵢ) + cᵢ` 라 프록시 중심이 결손부에 안 찍히면
점이 생길 자리가 없다는 것. **그 사슬 자체는 맞지만, 이 입력에서는 중심이 찍혔다.**

즉 08-28 의 0점은 **구조의 필연이 아니라 그 입력에서 일어난 일**이었다.
구조는 "중심이 안 찍히면 못 메운다"까지만 말하고, **언제 안 찍히는지는 말해주지 않는다.**

### 게이트 ①도 잘못 잡았다

처음 통과선은 **유효 보충점 1,000개**였다. 완벽한 모델이 결실부에 2,315점을 넣는다는
자체 테스트에서 그 43%로 정했다. **틀린 통계였다.**

모델의 출력 예산은 **8,192점 고정**이고 그걸 유물 전체에 퍼뜨린다.
결실부를 **성기게라도 다 덮으면** 개수가 적어도 형상은 복원된 것이다.
실제로 보충점 777개로 78.5%를 덮었다.

**커버리지 순증으로 바꿨다** (통과선 0.50). 이건 자체 테스트에서 이미 0~1에 보정된 값이라
결과를 보고 만든 기준이 아니다. 옛 개수 기준도 참고로 같이 찍는다.

![EA_028 결과](images/결과-1-ea028.png)

**출력이 입력의 최저점에서 정확히 끝난다.** 아래로 한 점도 나가지 않았다.

### AdaPoinTr 는 실제로 더 나은 모델이다 — 다만 방향이 다르다

숫자를 보면 확장판이 PoinTr 보다 **모든 면에서 낫다.**
잔존부를 4배 이상 정확히 재현하고(3.5 → 0.8mm), 엉뚱한 보충점을 12분의 1로 줄였다(960 → 82).

**그런데 그 개선이 전부 "입력을 더 충실히 재현하는" 방향이다.**
막힌 지점은 "입력에 없는 것을 만들어내는" 쪽인데, 거기는 0 그대로다.

### 세 가지 가설 중 무엇이었나

[2] 를 쓸 때 두 결과가 다를 수 있는 이유를 셋으로 적어뒀다.

| # | 가설 | 판정 |
| ---: | --- | --- |
| 1 | 모델이 다르다 (PoinTr → AdaPoinTr) | **아니다.** [1] 에서 모델만 바꿨는데 0 그대로 |
| 2 | **입력이 다르다** | **이것이다.** 같은 모델이 [2] 는 메우고 [1] 은 안 메운다 |
| 3 | 합성 결손이라 쉬웠다 | 2번과 얽혀 있다. §5 3번에서 분리 |

**"굽다리 없는 고배"는 부분으로 읽히고, "바닥 없는 돔"은 완형으로 읽힌다.**
모델은 후자에서 *복원에 실패한 것이 아니라 복원할 것이 없다고 판단했다.*

### 이번 결과로도 안 바뀌는 것

| | 왜 |
| --- | --- |
| 출력 8,192점 | 프록시 수 × 프록시당 점수가 학습 시점 고정. **출력 점간격 1.23mm 는 유물이 작아서**지 해상도가 좋아서가 아니다 |
| 마스크 입력 없음 | 우리가 판정한 결손을 넘겨줄 통로가 없다 |
| 전체 재샘플링 | `NFR-ETH-003` 관측/추정 노드 분리 불가 |

그리고 **형상 충실도는 아직 안 쟀다.** 그림의 재구성된 굽다리는 위치는 맞지만
**투창도 돌대도 없다.** 이 파이프라인이 `--nfold` 로 세고 있는 바로 그 구조다.
커버리지는 "거기 점이 있나"만 보지 "맞는 모양인가"는 안 본다.

## 3.5 실제 복원 대상 71489 — 아무것도 안 만든다

[1][2] 가 "남은 형상이 부분으로 읽히나"로 갈린다는 걸 보였으니,
**정작 우리 유물은 어느 쪽인지** 넣어봤다. `run_71489.py`

71489 는 아가리가 둘레 전체 톱니로 깨진 고배라 **[2] 의 `rim`(순증 0.961)과 닮았다** —

| 입력 | 보충점 / 8192 | 아가리 위로 연장 |

| `gupdari-71489/in/A_normal.glb` (사진 → TRELLIS) | **20** | **0** |

**안 된다.**

**그 설명은 틀렸다.** §3.6 에서 확인했다 — 입력은 이미 톱니 아가리를 갖고 있다.

## 3.6 마스크로 잘라서 넣어봤다 — 여전히 안 되고, 진짜 이유가 나왔다

§3.5 의 가설대로 **구멍을 만들어 주면 되는지** 확인했다. `run_71489_cut.py`

v32 결과 GLB 가 `region_carried` / `region_filled` 두 노드로 나뉘어 있다
(`NFR-ETH-003` 노드 분리). **`region_filled` 이 결손 영역 그 자체**이므로,
그 근처의 carried 점을 지워 부분 점군을 만들었다 — 120,000점 중 23,502점(19.6%).

| | 값 |
| --- | ---: |
| 보충점 | **71 / 8192** |
| 결손 커버리지 순증 | **0.000** |
| v32 채움과 일치 | 0.620 |
| (비교) 안 자르고 넣었을 때 | 보충점 20 |
| (비교) [2] `rim` | 순증 **0.961** |

![마스크 컷](images/결과-71489-cut.png)

### 그림이 두 가지를 알려준다

**1. 내 앞선 설명이 틀렸다.** 1·2번 패널을 보면 **carried 는 이미 톱니 아가리를 갖고 있다.**
TRELLIS 가 아가리를 매끈하게 메운 게 아니다. `경계변 0` 은 껍질이 두께를 갖고 뒤로
감싸 닫혀서지, 아가리가 평평해서가 아니었다. **자르기 전에도 입력에 구멍이 있었다.**

**2. 그런데도 모델은 아무것도 안 한다.** 4번 패널의 v32 채움과 비교하면
채워야 할 곳이 명확한데 3번 패널에는 보충점 71개가 흩뿌려져 있을 뿐이다.

### 진짜 이유 — 결손의 **종류**가 다르다

| 결손 종류 | 예 | AdaPoinTr |
| --- | --- | --- |
| **국소 덩어리 결손** | [2] 의 `rim`(각도 한 구간) · `side` · `bottom` | **메운다** 0.785~0.996 |
| **둘레 전체 침식** | **71489 아가리** — *"둘레 전체가 톱니로 깨져 있었다"* | **0** |
| **한쪽 전체 소실** | [1] `EA_028` 하부 몸통 | **0** |

**기여자 08-26 이 이미 적어둔 것이다** — PoinTr 부적합 사유 ③ *"침식형 결손을
결손으로 인식 못 함"*. AdaPoinTr 도 같다.

둘레 전체가 고르게 깎이면 **그 깎인 윤곽 자체가 이 그릇의 모양**으로 읽힌다.
모델에겐 "여기가 원래 더 있었다"고 볼 근거가 형상 안에 없다.
`[2]` 의 `rim` 이 됐던 건 **나머지 둘레가 멀쩡해서 대비가 생겼기** 때문이다.

> 그래서 71489 는 AdaPoinTr 로는 안 된다. 반면 **회전대칭 가정은 바로 이 경우에 강하다** —
> 둘레 전체가 깎여도 남은 프로파일에서 `r(y)` 를 세우면 복원된다. v32 가 하는 일이다.

## 3.7 A_normal.glb 복원 결과 — 형상으로 보기

**출력은 사실상 입력을 8192점으로 다시 뿌린 것이다.** 가운데 열의 파란 형상이
왼쪽 회색과 같은 실루엣이고, 아가리의 V자 결손도 그대로 남아 있다.
오른쪽 v32 와 비교하면 무엇을 안 했는지가 분명하다.

블렌더에서 열어볼 수 있게 PLY 로도 내보냈다.

```text

work/restored_adapointr/A_normal_input.ply       입력 12000점 (비교용)
```

### 손상 양상을 내가 단순화했었다

§3.6 에서 71489 를 *"둘레 전체 침식"* 으로만 적었는데, 그림을 보면 **그보다 심하다** —
아가리에 깊은 V자 결손이 있고 측면에도 큰 결실이 있다. **국소 덩어리 결손이 섞여 있다.**

그런데도 0 이다. 그래서 판정 기준을 다시 쓰면 이렇다.

> **둘레 어디에도 "온전한 기준 테두리"가 없다.**
> [2] 의 `rim` 이 됐던 건 나머지 둘레가 멀쩡해서 **거기서 벗어난 각도 구간**이
> 형상 안에서 보였기 때문이다. 71489 는 둘레 전체가 제각각이라 기준이 없다.
> 모델에게 이 울퉁불퉁한 윤곽은 **그냥 이 그릇의 모양**이다.

이건 `[2]` 의 국소 결손이 잘 된 것과 모순되지 않는다 — 국소인지 아닌지가 아니라
**비교할 기준이 남아 있는지**가 갈린다.

**제외 판단은 맞았다. 이유가 정확해졌다.**

| | 전 | 후 |

EA_028 보다 더 확실하게 "완형"으로 읽힌다.

| | 왜 |
| --- | --- |

## 4.5 정규화 누출 — §1~4 의 숫자를 뒤집는다 (2026-09-14 밤)

파인튜닝을 준비하다가 **내 실험 설계의 결함**을 찾았다.

`make_pairs.py` 의 `normalize()` 가 `partial` 을 **`complete` 의 중심·축척**으로 옮긴다.
그러면 잘려나간 쪽에 빈 공간이 남고, **모델이 원래 크기를 액자에서 읽는다.**
실제 유물에는 complete 가 없으니 그 단서가 없다.

같은 쌍·같은 가중치로 정규화만 바꿔 쟀다.

### 5.6 sim-to-real 격차 — 파단면은 원인이 아니다 (기각)

§5.5 가 남긴 격차(합성 0.913 vs 실제 71489 는 훨씬 못함)의 후보 1번을 검증했다.

> **가설.** 합성 결손은 점을 **지우기만** 해서 경계가 두께 0 의 깨끗한 절단이다.
> 실제 도기는 두께가 있어(71489 manifest `thickness 0.008`) 깨지면
> **안쪽벽과 바깥벽을 잇는 단면**이 드러난다. 그 차이가 격차의 원인 아닌가.

`fracture_points()` 로 결손 경계에 두께 벽을 세웠다.
TRELLIS 메시는 두께 있는 닫힌 껍질이라 한 `(h,θ)` 칸에 바깥벽·안쪽벽 점이 같이 있다 —
칸마다 `r` 의 최대/최소가 그 두 벽이고, 그 사이를 채우면 파단면이 된다.

**같은 결손 파라미터**(평균 0.479, min/max 동일)에 파단면만 켜고/껐다.

| | 깨끗한 절단 | 파단면 2.3% | **파단면 8.2%** |
| --- | ---: | ---: | ---: |
| 사전학습 | 0.023 | 0.021 | 0.021 |
| 파인튜닝 v2 | 0.936 | 0.924 | **0.898** |

**차이가 없다.** v2 가 0.936 → 0.898 로 4% 떨어질 뿐이고, 71489 의 격차를 설명하기엔
턱없이 작다.

> **중간에 내 실험이 한 번 틀렸다.** 처음엔 파단면을 칸당 14점만 넣어
> 입력 2048점 중 **48점**밖에 안 들어갔다. 실제 71489 는
> (아가리 둘레 44cm × 두께 0.8cm ≈ 35cm² / 전체 ~400cm²) **약 9%** 라
> 2048점 중 ~180점이어야 한다. **4배 과소**였다.
> 칸당 52점으로 올려 8.2%(168점)를 맞추고 다시 쟀다. 결론은 같았다.

### 5.6.1 가설 3·4 도 기각 — 남는 것은 상류 도메인뿐

**가설 3 — 손상 형태 복잡도.** 71489 는 V자 노치 + 측면 결실 + 톱니가 섞여 있는데
내 합성은 한 번에 한 패턴만 낸다. `mixed_mask()` 로 `ragged+rim+side` 를 동시에 적용하고
**손상량을 맞춘 순수 ragged 대조군**과 비교했다.

| | 손상량 | 사전학습 | v2 |
| --- | ---: | ---: | ---: |
| 순수 `ragged` (대조군) | 0.402 | 0.026 | **0.964** |
| `ragged+rim+side` 혼합 | 0.393 | **0.235** | **0.954** |

v2 는 차이가 0.01 로 **없다.** (사전학습이 0.026 → 0.235 로 9배 오른 건 별개 현상이다 —
혼합이 국소 노치를 만들어 §3.7 의 "기준 테두리" 조건을 되살린다. 우리 결론과 모순되지 않는다)

**가설 4 — 표면 잡음.** 입력 점에만 가우스 잡음을 주입했다(정답은 깨끗하게 둔다).

| | 실치수 | 사전학습 | v2 |
| --- | ---: | ---: | ---: |
| 잡음 없음 | 0 | 0.025 | 0.852 |
| σ=0.003 | 0.22mm | 0.025 | 0.845 |
| σ=0.008 | 0.60mm | 0.020 | 0.852 |
| σ=0.015 | 1.13mm | 0.015 | 0.868 |

**평평하다.** 잡음은 영향이 없다.

> ### 여기서 내 지표가 한 번 더 틀렸다
>
> 처음 쟀을 때 **잡음이 클수록 점수가 올랐다** (0.936 → 0.980). 말이 안 되는 방향이라 파보니
> δ 를 `partial` 점간격에서 뽑고 있었고, **잡음이 그 간격을 키워 문턱이 헐거워진** 것이었다.
>
> ```text
> 잡음 없음  partial 간격 0.0246 → δ 0.0739
> σ=0.015    partial 간격 0.0299 → δ 0.0898   (+22%)
> complete   간격 0.0176 → δ 0.0528           (잡음 무관)
> ```
>
> `--delta-src complete` 를 넣어 다시 쟀다. 그러자 평평해졌다.
>
> **부수 효과:** `complete` 기준 δ 는 `partial` 기준보다 **더 엄격**하다
> (점이 4배 많으니 간격이 좁다). 그래서 같은 결과의 절대값이 0.936 → 0.852 로 내려간다.
> **§5.5 까지의 숫자는 전부 `partial` 기준이다.** 모델 간 비교는 같은 문턱을 썼으므로
> 유효하지만, **절대 수준은 문턱 선택에 달렸다**는 점을 같이 읽어야 한다.

### 5.6.2 네 가설의 최종 판정

| # | 후보 | 효과 | 판정 |
| ---: | --- | --- | --- |
| 1 | 파단면 (두께 단면) | 0.936 → 0.898 | **기각** |
| **2** | **상류 도메인** — 학습은 *온전한* 사진의 TRELLIS, 71489 는 *깨진* 사진의 TRELLIS | 측정 불가 | **소거법으로 남음** |
| 3 | 손상 형태 복잡도 | 0.964 → 0.954 | **기각** |
| 4 | 표면 잡음 | 평평 | **기각** |

**내가 통제할 수 있는 셋을 전부 확인했고 어느 것도 격차를 설명하지 못했다.**
남은 것은 우리가 못 건드리는 상류 단계다 — TRELLIS 가 *깨진* 유물 사진을 재구성할 때
만드는 것이, *온전한* 유물 사진으로 만든 학습 완형과 다르다는 것.

> **소거법은 증명이 아니다.** 내가 생각 못 한 5번째 원인이 있을 수 있다.
> 다만 **합성 데이터를 더 정교하게 만드는 데 투자할 이유는 사라졌다** — 그게 실질적 결론이다.

### 5.6.3 메시화를 두 번 고쳤다 — 투창과 해상도

**문제 1. 투창을 다 막아버렸다.** 원인을 갈라 보니 모델이 아니라 **내 메시화**였다.

```text
입력 12만점 기준 굽다리 빈 칸 248 중
  모델 출력이 점을 넣은 칸   67 (27%)   ← 모델은 73% 를 열어 둔다
  내 fill_unknown 이 메운 칸  248 (100%)  ← 범인
```

**문제 2. 관측부까지 재샘플링했다.** 출력 8,192점 전체를 격자로 다시 만드니
원본 정점 **0.71mm 가 1.90mm 로** 벌어지고 텍스처도 잃었다.
**관측부는 모델이 개선할 것이 없는데** 손해만 봤다.

#### 고친 것 — 2노드 분리 (`make_mesh_2node.py`)

![2노드 분리](images/결과-71489-2노드.png)

| | 이전 | **지금** |
| --- | --- | --- |
| `region_observed` | 8,192점 → 격자 재구성 | **원본 94,877정점 무수정** |
| 관측부 해상도 | 1.90mm | **0.71mm** |
| 관측부 텍스처 | 없음 | **원본 유지** |
| 관측부 투창 | 격자가 뭉갬 | **원본 그대로** |
| `region_ai` | 전체의 8.8% | 결손 칸만 (F=8,636) |

v32 의 `region_carried`(무수정)/`region_filled` 와 같은 구조다 (`NFR-ETH-003`).

#### 그리고 n-fold 를 붙였다

![투창 보존](images/결과-71489-투창.png)

패치가 여전히 굽다리 투창을 덮었다. 크기·θ폭 문턱으로는 못 가른다 —
**파이프라인이 겪은 그대로**다 (`투창-n-fold-판정.md`: *"θ폭 70°·80° 짜리가 있어
문턱을 열면 진짜 파단까지 샌다"*). 그래서 같은 해법을 썼다: **띠별 θ 관측비율에 푸리에.**

**독립 재구현이 그쪽 측정을 재현했다** (96×144, 같은 해상도):

| 띠 | `투창-n-fold-판정.md` | 내 구현 |
| --- | --- | --- |
| 굽다리 하단 h 0~10 | 1-fold | **1-fold** ✓ |
| 띠 A h 8~18 | **4-fold** | **4-fold** ✓ |
| 띠 B h 27~37 | **3-fold** | **3-fold** ✓ |
| 바리 h 55~65 | 1-fold | **1-fold** ✓ |

네 띠 전부 1위 조화가 맞는다. 비중 값은 정규화가 달라 다르지만 **순위가 같다.**
주기 띠는 h 0.07~0.46 — 두 투창 단을 덮는다.

주기 띠 안에서는 θ폭 문턱을 풀어 준다. 결과:

| 굽다리 투창 두 단 구간 (빈 칸 1,068) | 투창 인식 | |
| --- | ---: | ---: |
| 문턱만 | 499 | 47% |
| **n-fold** | **678** | **63%** |

**오탐은 안 늘었다** — 바리(h>0.5) 오판정이 2칸으로 그대로다.

> **남은 37%.** 성분이 투창끼리 또는 굽 아래 틈과 이어져 θ폭 180° 를 넘거나,
> 띠 경계에 걸쳐 빠진다. 파이프라인도 같은 지점에서 *"`--nfold 6` 은 재검토 대상"* 으로
> 열어둔 상태라 여기서 더 밀면 그쪽 미해결 과제와 겹친다.

### 5.6.4 회전 TTA — 출력 8,192점 상한을 우회한다

`num_points: 8192` 는 학습 시점에 고정이라 추론에서 못 늘린다. 그런데 **이 유물은
회전체다** — 축 둘레로 돌리면 물체는 그대로인데 모델은 회전 불변이 아니라 다른 답을 낸다.
돌려 넣고 되돌려 합치면 **분산이 줄고 밀도가 runs 배**가 된다.

```python
for k in range(runs):
    a = 2*pi*k/runs
    out = infer(model, rot(pts, +a))
    merged.append(rot(out, -a))          # 되돌린다
```

**합성 깊이 0.40~0.50 (71489 수준)**

| runs | 커버리지 순증 | 출력 점수 |
| ---: | ---: | ---: |
| 1 | 0.913 | 8,192 |
| 4 | **0.970** | 32,768 |
| 8 | **0.984** | 65,536 |

**실제 71489**

| | 1회 | **TTA 8회** |
| --- | ---: | ---: |
| 보충점 | 253 | **2,946** |
| 아가리 위로 연장 | 43 | **352** |
| 출력 점간격 | 1.47mm | **0.67mm** |

**해상도 상한이 사라졌다.** 0.67mm 는 원본 메시(0.71mm)보다 촘촘하다 —
§5.6.3 에서 "2.7배 성기다"고 적은 한계가 여기서 풀렸다.

그러면 이제 **격자가 병목**이다. 96×144 로는 패치 정점이 4,700개인데
144×216 으로 올리면 10,611개가 된다. 점이 충분하므로 격자를 올리는 것이 바로 이득이다.

| 격자 | 투창 인식 | 결손 칸 | 패치 |
| --- | ---: | ---: | --- |
| 96×144 | 793 | 4,340 | V=4,700 F=8,754 |
| **144×216** | 1,983 | 10,088 | **V=10,611 F=20,118** |

> **비용은 추론 8배다.** 71489 한 점에 수십 초라 문제가 안 되지만,
> 합성 900쌍 평가에 쓰면 8배가 된다.

### 5.6.5 sim-to-real — 사진 단계에서 깨서 TRELLIS 를 태운다 (**중단**)

§5.6.2 가 소거법으로 남긴 원인은 **상류 경로**뿐이었다.

```text
학습 완형   온전한 사진 ──TRELLIS──▶ 3D ──내가 절단──▶ partial
71489      깨진   사진 ──TRELLIS──▶ 3D                  ← 경로가 다르다
```

3D 를 아무리 정교하게 깨도 이 차이는 안 없어진다. **사진을 먼저 깨면** 없어진다.

#### 어떻게 깼나

`run_trellis_batch.py` 주석에 답이 있었다 — *"알파 있으면 rembg 건너뜀"*.
**알파를 뚫으면 TRELLIS 가 그 자리를 배경으로 본다.**

```text
① pipe.preprocess_image()  →  배경 제거된 RGBA
② 아가리 쪽 알파를 가로 위치마다 다른 높이로 지운다 (저주파 파형)
③ 그 PNG 를 TRELLIS 에 다시 넣는다
```

![사진 훼손](images/실험-사진훼손.png)

> **한 번 죽었다.** 파이프라인을 직접 로딩하면 `_apply_patches()`(flex_gemm)와
> `pipe.cuda()` 가 빠져 `Input type (cuda) and weight type (cpu)` 로 터진다.
> `run_trellis_batch.load_pipeline()` · `run_one()` 을 **그대로 불러 쓰도록** 고쳤다.

#### 정렬 — 굽다리를 자로 쓴다

TRELLIS 는 매번 단위 정육면체로 정규화한다. 아가리를 자른 쪽은 bbox 가 달라져
**축척과 높이 원점이 어긋난다.** 그대로 쌍을 만들면 `complete_removed` 가 통째로 틀린다.

**굽다리는 양쪽 다 온전하다.** 그걸 기준으로 맞춘다 (`align_damaged.py`).

```text
1. 회전축을 +Z 로 세우고 축 위로 중심 이동
2. 바닥(min h)을 0 으로        ← 굽 바닥은 안 깨졌으니 공통 원점
3. 남은 자유도는 축척 하나 → r(h) 프로파일이 가장 겹치는 s 를 찾는다
```

![정렬 검증](images/실험-정렬검증.png)

9점 전부 맞았다. 프로파일 RMSE 중앙 **0.019** (최악 경주 2027 의 0.048 — 굽 바닥이 조금 어긋난다).

#### 발견 — TRELLIS 가 스스로 더 만든다

사진에서 위 **35%** 를 지웠는데 3D 에서는 **24%만** 없어졌다 (남은 높이 중앙 76%).
**TRELLIS 가 잘린 사진을 보고 바리를 조금 복원한다.** 실제 71489 에서도 같은 일이
일어났을 테니 현실적이지만, 결손 깊이가 71489(~48%)보다 얕다.

그래서 **깊은 세트**(`--base 0.55`)를 하나 더 만든다. 그래야 v2 학습 데이터와 깊이가
같아져 **상류 경로 변수만** 남는다.

| 세트 | 상류 경로 | 3D 결손 깊이 |
| --- | --- | ---: |
| v2 학습 데이터 | 3D 절단 | 0.35 |
| 얕은 사진훼손 | **사진→TRELLIS** | 0.24 |
| 깊은 사진훼손 | **사진→TRELLIS** | ~0.45 ← v2 와 깊이 맞춤 |

---

### 5.6.6 깊은 세트 — TRELLIS 가 **굽다리를 못 세운다** (2026-09-16)

`--base 0.55` 로 위 **55%** 를 지운 사진 9장을 TRELLIS 에 태웠다. 9점 다 나왔다.
그런데 정렬에서 걸러 보니 **2점만 쓸 수 있었다.**

| 세트 | 통과 | 프로파일 RMSE | 남은 높이 |
| --- | ---: | ---: | ---: |
| 얕은 (`--base 0.35`) | **9/9** | 0.004~0.048 | 중앙 77% |
| 깊은 (`--base 0.55`) | **2/9** | 통과분 0.014·0.032 | 중앙 53% |

#### 무엇이 깨졌나

정렬이 아니라 **상류가 깨졌다.** 사진에서는 **위만** 지웠으니 굽은 멀쩡해야 하는데,

```
경주_8478  깊은훼손  r(h) = 88 146 197 208 ... 474 494 501 499 484
                             ^^ 아래부터 단조증가 — 굽 벌어짐이 아예 없다
경주_8478  원본      r(h) = 329 334 311 238 209 195 190 168 ... 495 502
                             ^^^ 굽 벌어짐   ^^^ 허리   ^^^ 바리
```

굽다리가 통째로 사라지고 **위로 벌어지는 원뿔**이 됐다. 3점이 이랬다.
나머지 4점은 굽은 있는데 **비율이 달라졌다** — 경주_887 은 훼손본 허리가 원본보다
**더 낮게**(31% vs 36%) 나왔다. 위만 지웠는데 그럴 수는 없다.

> 입력 화소가 절반 아래로 내려가면 TRELLIS 는 **없는 부분을 빼먹는 게 아니라
> 남은 부분까지 다시 빚는다.** 이건 3D 를 깎아 만든 합성 데이터에는 없는 성질이고,
> 71489 가 학습 분포에서 벗어나는 이유를 상류에서 한 번 더 뒷받침한다.

#### 대조군 — TRELLIS 는 실행마다 달라진다. 그 폭은?

*"트렐리스 생성할 때마다 달라서 완전히 일치할 수가 없다"* — 맞는 지적이라 직접 쟀다.
**같은 사진**(훼손 없이 `--base 0 --amp 0`)을 TRELLIS 에 다시 태우고 같은 잣대로 비교했다.

재실행 대상 4점 중 **3점(경주 5756·5757·8478)이 깊은 세트에서 탈락했던 바로 그 유물**이다.
*"저 유물들이 원래 어려운 것 아니냐"* 를 같이 배제하려고 그렇게 골랐다.

| 유물 | 허리 축척 | 정합 축척 | 프로파일 RMSE | 굽 검사 |
| --- | ---: | ---: | ---: | --- |
| 경주_2027 | 1.003 | 1.006 | 0.0137 | 통과 |
| 경주_5756 | 0.998 | 0.998 | 0.0037 | 통과 |
| 경주_5757 | 0.957 | 0.989 | 0.0058 | 통과 |
| 경주_8478 | 0.998 | 1.001 | 0.0041 | 통과 |

| | 프로파일 RMSE |
| --- | ---: |
| **같은 사진 재실행** (대조군) | 중앙 **0.0049** · 최대 **0.0137** |
| 얕은 사진훼손 (통과 9/9) | 0.004 ~ 0.048 |
| 깊은 사진훼손 (탈락 4점) | **0.123 ~ 0.235** |

깊은 세트의 실패는 실행 간 잡음 **최대치의 9~17배**다.
게이트 `--max-rmse 0.06` 은 잡음의 4배 위, 실패의 절반 아래에 있다 —
**잡음을 거르는 게 아니라 붕괴를 거른다.**

결정적인 것은 **굽 검사**다. 실행 간 차이로는 **4/4 통과**하는데
깊은 세트에서는 같은 유물이 *"굽 벌어짐 없음"* 으로 **3점 탈락**했다.
`경주_8478` 은 재실행에서 굽이 멀쩡히 나오고 깊은 훼손에서만 사라졌다 —
**유물 탓도, 난수 탓도 아니고 입력 화소가 줄어서 생긴 일이다.**

덤으로 **허리 기준점이 편향 없음**도 확인됐다: 같은 물건을 두 번 태웠을 때
허리 축척 중앙 **0.998**, 폭 0.957~1.003 (참값 1.000).

#### 정렬을 두 군데 고쳤다

**① 허리를 축척 기준점으로.** 굽다리의 굽은 원뿔이고 **원뿔은 자기닮음**이라
`r(h)` RMSE 만 보면 최소가 평평하다. 실제로 경주_8478 이 탐색 상한 **1.600** 까지
밀려 올라갔다. 잘록한 허리는 길이 자체를 갖는 지형지물이라 축척을 박는다.
얕은 세트에서 **허리 축척과 정합 축척이 3% 안에서 일치**해 이 기준점을 검증했다.

**② 굽 검사 + 정합 RMSE 게이트** (`foot_ok`, `--max-rmse 0.06`).
굽 벌어짐이 없거나 정합이 안 되면 쌍에서 뺀다.

#### 쌍으로는 6형상만 남았다

`make_pairs_photo.py` — 정렬 점군 → `make_pairs` 와 같은 형식.
결손 마스크는 3D 대응이 없어 **거리**로 정한다 (partial 점간격 중앙값 × 3).
회전체라 축 둘레 회전은 강체 변환이므로 **40각도로 불려** 200쌍을 만들었다.
결손률 0.63~0.80 이 범위를 벗어난 것은 뺐다 (깊은 세트 2점은 0.91·0.93 으로 탈락).

> 정직하게 적으면 **깊은 세트 실험은 목표를 이루지 못했다.** 깊이를 v2 학습
> 데이터에 맞추려 했는데, 그 깊이에서는 TRELLIS 자체가 무너져 대조가 성립하지 않는다.
> 대신 **상류 경로가 원인이라는 가설을 직접 지지하는 관찰**을 얻었다.

#### 여기서 멈췄다 — 왜 (2026-09-17)

얕은 세트 **200쌍(6형상)** 은 `work/pairs_photo/` 에 만들어 뒀지만
**학습에 한 번도 안 썼다.** 이유 둘.

**① 표본이 너무 얇다.** 6형상 200쌍으로 학습해 16형상 1,920쌍(v3)과 비교하면
차이가 상류 경로 때문인지 표본 수 때문인지 못 가른다. 대조가 성립하지 않는다.

**② §5.11 이 다른 길로 같은 증상을 풀었다.** 실제 유물이 합성만큼 안 나오던 것을
*"상류 경로가 달라서"* 로 보고 이 줄기를 팠는데, 실제 원인의 큰 몫은
**학습 분포가 얕아서**였다. `slant` 패턴을 넣자 깊은 결손이 **0.510 → 0.985** 로 올랐다.
증상이 풀렸으니 이 줄기의 우선순위가 밀렸다.

> **가설이 기각된 것이 아니다.** *"학습 완형은 온전한 사진의 TRELLIS, 71489 는 깨진
> 사진의 TRELLIS"* 라는 차이는 **여전히 있고 여전히 미검증**이다. 소거법으로 남은
> 것이지 증명된 적이 없다. 다시 열려면 **완형 사진을 더 모아** 얕은 세트를
> 16형상 규모로 키우는 것이 먼저다.

`work/pairs_photo/` 와 `photo_damaged*` · `trellis3d_damaged*` · `aligned*` 는
**지우지 않는다** — 다시 열 때 TRELLIS 를 유물당 9.5분씩 다시 태우지 않으려면 필요하다.

#### 세 가지가 색을 뭉개고 있었다

**① 도너 k개의 중앙값** (v3~v5). 결손 호에서 먼 텍셀도 **같은 가장자리 12개**만
보게 돼 호 전체가 한 색으로 눕는다. 중앙값은 튀는 값도 지우지만 **무늬도 지운다.**
→ 관측 띠를 그대로 둘레에 붙이는 **거울 타일링** 으로 바꿨다.
한 주기를 `seg + seg[::-1]` 로 잡으면 이어붙인 자리의 양쪽 값이 같아 끊기지 않는다.

**② 원본 텍스처를 정점색으로 굽고 있었다.** `visual.to_color().vertex_colors` 는
1024x1024 텍스처를 정점 94,877개로 줄인다 — 거기서 디테일이 죽는다.
→ 표본점의 무게중심 좌표로 UV 를 보간해 **원본 텍셀을 직접** 읽는다.

**③ 안쪽벽이 섞여 어두웠다.** 원본은 두께 있는 닫힌 껍질이라 한 `(h,θ)` 텍셀에
바깥벽과 **안쪽벽**이 같이 들어간다. 안쪽은 그늘져 어둡다 —
실측 **표본의 52%가 안쪽벽**이었다.
→ 면 법선이 축에서 바깥을 보는 표본만 쓴다. 이음새 밝기차 **-4.2 → -1.2**.

그리고 텍셀당 표본이 3개뿐이라 **산탄잡음**이 남는데, 이걸 두고 타일링하면
잡음까지 복사돼 국소 편차가 관측의 **190%** 가 됐다. 결손부를 흐리면 도로 단색이 되므로
**관측 텍셀 안에서만** 정규화 합성곱으로 다듬는다 (`--tex-clean`).

### 5.8.1 울퉁불퉁함과 부착면 틈 (2026-09-16 저녁)

![울퉁불퉁·틈](images/재질-울퉁불퉁-틈.png)

이면각(5.91°, 관측 98%)이 맞는데도 **눈으로는 울퉁불퉁했다.** 잣대가 잘못 잡혀
있었다 — 이면각은 **면과 면 사이 각**이라 국소만 본다. 큰 파도는 못 잡는다.

#### 잣대를 하나 더 만들었다 — θ 흔들림

행마다 36각도의 바깥 반지름을 재고 **변동계수**를 낸다. 회전체면 0 이다.

| | θ 흔들림 |
| --- | ---: |
| 관측 | 0.0307 |
| v11 | **0.0519** ← 관측의 1.7배 |
| v12~ | **0.0189** |

#### 고친 것 ① — 결손부를 회전체로 되돌린다 (`--axisym`)

토기는 물레로 빚은 회전체다. **결손부에서 각도마다 반지름이 다를 근거가 없다** —
모델 출력의 θ 변동은 정보가 아니라 잡음이다.

통째로 회전체를 만들면 관측면(0.0307 만큼 흔들림)과 만나는 이음새에서 단이 진다.
그래서 **이음새에서 멀어질수록** 회전체 가중을 올린다 (`--axisym-ramp` 칸에 걸쳐).
행별 대표 반지름은 **중앙값**으로 잡아 튀는 칸을 뺀다.

돌대는 안 깎인다 — 돌대는 h 방향 구조이고 여기서 지우는 것은 θ 방향이다.
실측 **98%** 로 살아남았다.

#### 고친 것 ② — 이음새를 관측 껍질 밑으로 깐다 (`--seam-tuck`)

패치 테두리는 144x216 격자에 갇혀 있는데 관측 조각의 진짜 가장자리는 그보다 잘다.
그래서 둘 사이가 어긋난다 — **중앙 2.5mm · 최대 5.1mm** (높이 15cm 환산).

팽창(`--dilate`)만 키우면 틈은 줄지만 패치가 관측면을 **뚫고 나온다.**
그래서 팽창을 3칸으로 키우고, 이음새 가까운 칸의 반지름을 **벽 두께의 0.5배만큼
안으로** 밀었다. 겹친 부분이 관측 밑으로 들어가 밖에서는 관측만 보인다.

**얼마나 막혔나** — 완성본을 다시 144x216 격자에 올려 빈 칸을 셌다
(투창 1,983칸은 뚫려 있어야 정상이라 뺀다).

| | 진짜 구멍 |
| --- | ---: |
| v11 | 128칸 |
| v12~ | **27칸** |

#### 고친 것 ③ — 밝기만 이음새에 맞춘다 (`--tex-blend`)

거울 타일링은 무늬를 살리지만 **얼룩까지 그대로 옮긴다.** 이 유물은 한쪽이 밝고
반대쪽이 어둡다 — 같은 높이 안에서도 각도별 밝기 표준편차가 **11.4**(전체 118 대비 10%)다.

얼룩은 회전대칭이 아니므로 **복원할 수 없다.** 대신 결손 호 양 끝에서 관측 밝기를
읽어 그 사이를 매끄럽게 잇는다 — 가장 약한 가정이다. 무늬(고주파)는 복사본 그대로
두고 **저주파 밝기만** 비율로 맞춘다. 이음새 **+12.0 → +8.0**.



#### 고친 것 ④ — 벽 두께를 두 번 잘못 재고 있었다

*"표면 두께가 안 맞아"* — 재는 방법 자체가 틀렸다. **두 번** 틀렸다.

| 방법 | h 0.70 칸에서 | 판정 |
| --- | ---: | --- |
| `r` 분위수 폭 (92%−8%) | **8.2mm** | 칸 안에서 **벽이 굽은 정도**까지 두께로 셌다 |
| 법선으로 바깥/안쪽 분리 후 중앙 `r` 차 | **0.9mm** | 파단 테두리에서 두 벽이 맞붙어(경계변 38,816) 값이 눌렸다 |
| **단면 빈틈** | **3.6mm** | 맞다 |

`(h, θ)` 칸 안에서 `r` 을 정렬하면 두 벽 사이가 **비어 있다.**

```
r 정렬:  0.568 0.571 0.575 0.578 0.582 0.585 0.589 │ 빈 틈 │ 0.605 0.609 0.612 0.616
         └────────── 안쪽벽 ──────────┘                      └──── 바깥벽 ────┘
```

그 틈에서 자르고 양쪽 중앙값을 뺀다. 굽음에도, 테두리에도 안 흔들린다.

**그리고 프로파일을 가우시안으로 밀고 있었다.** 굽/바리 이음은 22mm 인데 바로 옆
몸통은 7mm 다 — 그 봉우리가 양옆으로 번져 결손부 벽이 통째로 두꺼워졌다.
중앙값 필터는 봉우리를 옮기지 않는다.

| | 관측 대비 벽 두께 |
| --- | ---: |
| v13 (분위수 폭 + 가우시안) | **137%** |
| v14 (단면 빈틈 + 중앙값 필터) | **109%** |

#### 고친 것 ⑤ — 복원면이 **통째로 파묻혀** 있었다

#### 원인 둘

**① 관측 r 을 점유율 없이 믿었다.** §5.8.1 ⑤ 의 `--outer-shift` 는 *"행마다 관측
바깥 반지름에 맞춘다"* 인데 **그 높이에 관측이 둘레의 얼마나 남았는지**를 안 봤다.

| 높이 | θ 점유 | 관측 r | 모델 r |
| --- | ---: | ---: | ---: |
| 0.70~0.73 | **31%** | 0.808 ← 파단선 끝 | 0.757 |
| 0.83~0.87 | **25%** | 0.652 | 0.739 |
| 0.60~0.63 | 53% | 0.669 | 0.665 ← 여기선 일치 |

점유 50% 넘는 곳에서는 관측과 모델이 **0.003** 차이로 맞는다. 낮은 곳에서만 어긋나고,
그 값(= 비스듬한 파단선의 양 끝)을 둘레 전체에 돌려서 챙이 생겼다.
**71489 는 139/144 행에서 둘레가 많이 남아 이 결함이 안 드러났다.**

→ `--outer-cov-lo/hi` 로 **θ 점유 가중**. 점유 30% 미만이면 모델을 목표로 쓴다.
모델의 90분위는 관측 바깥면보다 살짝 바깥이라, **둘 다 믿을 만한 행에서 그 차이를 재서**
모델 쪽을 같은 자로 옮긴다(자동 보정).

**② 흩뿌려진 후광까지 격자에 넣었다.** 메시화 **전** 점군을 보면 답이 나온다.

![점군 구름](images/실험-점군-구름.png)

빽빽한 심과 후광이 나뉘는데 후광까지 쓰니 그 칸의 반지름이 밖으로 끌려갔다.

→ `--density-keep 0.70`. 국소 밀도(12번째 최근접까지 거리) 상위 70%만 쓴다.
**관측과 겹치는 점은 안 건드린다** — 걷어내는 것은 모델이 새로 만든 점뿐이다.

### 그리고 메시화를 세 군데 더 고쳤다

**① 밀도 임계를 높이 띠마다** (`--density-bands 24`).
전역 하나로 잡으니 **아가리 위로 뻗은 끝단이 몰살당했다** — 71489 에서 전체 새 점은 70%
살아남는데 관측 위쪽 연장부는 **5%**(311 → 17점)만 남고 연장 높이가 +17.8mm → +2.6mm 로 잘렸다.
거기는 후광이라서가 아니라 **구조상 점이 적다.** 띠마다 백분위를 따로 잡으면 그 편향이 사라진다
(고적_13472 연장 +0.6mm → **+5.3mm**). 띠 전체가 후광인 경우를 막으려고 전역 상한(`--density-cap`)을 같이 건다.

**② 마스크 닫기와 작은 섬 제거** (`--mask-close 2` `--min-island 40`).
결손이 흩어져 있으면 패치도 여러 조각이 된다 — 구멍마다 따로 만들어지니 그건 정상이다.
닫기는 잔구멍만 메운다. *닫기의 침식 단계가 배열 경계를 배경으로 봐서 **맨 위·아래 행을 깎았다** —
아가리가 바로 맨 위 행이라 h 방향으로 가장자리를 복제해 덧댄다.*

**③ 부스러기 조각 날리기** (`--drop-loose 6` `--min-piece 300`).
허공에 뜬 파편을 버린다. **거리만으로는 안 갈렸다** — 굽다리 바로 옆이라 관측에 다 "닿아" 있었다.
크기를 같이 봐야 한다. 조각 크기가 쌍으로 나오는데(41256 / 1804 / 692·692 / … / 10)
**껍질이라 한 조각이 바깥벽·안쪽벽 둘로 세어지기** 때문이다.
71489 조각 17 → 3 (버린 면 1.2%) · 고적_13472 조각 30 → 10 (2.7%).

![조각 날리기](images/결과-조각날리기.png)

> **헛다리도 하나 짚었다.** 아가리 띠가 비어 보여 마스크를 의심했는데,
> 상위 10행이 **216/216 전부** 채우기로 잡혀 있었고 완성본의 θ 점유도 h 0.84~0.99 에서
> **전부 100%** 였다. 위에서 내려다본 렌더 각도(pitch +12°) 때문에 **그릇 안쪽 벽이 보인 것**이다.
> pitch 를 −6° 로 낮추니 사라졌다. **렌더 각도를 의심하는 것도 디버깅이다.**

그 칸은 **보호되어 영영 안 메워진다.** 반대 오판보다 조용해서 더 위험하다.

**② 깨진 가로살은 되돌린다** (`--fix-strut`).

**정상 창이 한 개도 안 걸치는 행만** 결손으로 되돌린다 (71489 184칸 · 고적_13472 0칸).
창 모양은 안 건드린다. 되돌린 자리는 지어내지 않는다 —
**그 높이의 다른 각도에는 살이 멀쩡하므로** 회전 복사로 가져온다.

세 번째 줄이 문제다. 굽다리 벽이 **θ 38°~122°, 85° 폭으로 통째로 없어서**
그 안에 있던 창도 벽과 같이 사라졌다. 깨진 벽과 창이 **하나의 빈 덩어리**로 이어진다.

투창 판정은 *"벽 속의 주기적인 구멍"* 을 찾는다. **벽이 없으면 볼 대상이 없다.**
판정이 틀린 게 아니라 판정할 것이 없었다. 그래서 전부 결손이 되고 민벽으로 메워졌다.

**자동으로 창을 찍어 넣기는 근거가 얇다.** 파이프라인이 이 구간을 4-fold 로 보는
확신도가 21~29% 다. 살아남은 위 단 창 3개도 간격이 110°·141°·109° 로 안 고르다.
이 상태에서 창을 만들면 **위치를 지어내는 것**이 된다.

| | 무엇 | 주장하는 것 |
| --- | --- | --- |
| **A (지금)** | 민벽으로 메우고 `region_ai` 로 표시 | "여기 벽이 있었다" — 창 위치는 주장 안 함 |
| B | 그 덩어리는 안 메움 | 아무것도 주장 안 함. 깨진 채로 남음 |
| C | n-fold 로 창을 회전 복사 | "창이 **이 자리에** 있었다" — 근거 21~29% |

**A 로 둔다.** 석고 복원 관례와 같다 — 없어진 부분은 메우되 무늬는 지어내지 않고
복원부임을 구분되게 둔다. 2노드 분리(NFR-ETH-003)가 그 역할을 한다.
C 는 n-fold 확신도 문턱을 걸고 **옵션으로만** 넣을 일이다. 이 유물에서는 안 걸린다.

> 이건 파이프라인의 한계로 적어 둔다. **벽이 남아 있으면 창을 지키고,
> 벽이 없으면 창도 못 지킨다.** 전자는 장치로 풀었고 후자는 안 푼다.

#### 이번엔 진단을 먼저 검증했다

§5.11 에서 `openwork_cells()` 에 잘못된 마스크를 넘겨 *"투창 0칸"* 이라고 적은 적이
있다. 그래서 이번에는 밖에서 `dense_occ` 를 다시 만들지 않고
**파이프라인이 쓰는 마스크를 그대로 떴다** (`--dump-mask`).
덤프가 빌드 로그와 같은 값(투창 1,862 · 결손 9,628 · 패치 13,551)인지,
`region_observed` 점유가 덤프 `occ` 와 맞는지(98.7%) 두 번 확인한 뒤에 쟀다.

### 밀도 절단은 투창과 결손을 못 가른다

푸아송은 빈 곳도 매끄럽게 덮는다(watertight 를 지향한다). 구멍을 열려면
**밀도가 낮은 정점을 버려야** 한다. 그런데 절단을 올릴수록:

```
절단 없음   결손 99.9% 메움  ·  투창  5.3% 열림    ← 투창까지 메운다
   15%      결손 13.3%      ·  투창 68.8%
   30%      결손  5.9%      ·  투창 82.9%          ← 결손도 안 메운다
```

**완벽한 상충이다. 중간값도 둘 다 어정쩡하다.**

> **왜 그런가.** 점군에서 **투창과 결손은 둘 다 "점이 없는 곳"** 이다.
> 구별할 정보가 **점 자체에 없다.** 밀도 절단은 *"점이 적은 곳을 버린다"* 일 뿐이라
> 둘을 같이 연다.
>
> **`(h,θ)` 격자 + n-fold 판정이 하는 일이 바로 그 정보를 밖에서 넣는 것이다.**
> 그래서 v22 가 두 축 모두에서 이긴다. 이건 격자가 더 똑똑해서가 아니라
> **정보를 하나 더 갖고 있어서**다.

### 매끈함 — 밀도가 균일하지 않다

| | 점 간격 (최근접 중앙) |
| --- | ---: |
| 관측 재현부 | 0.0085 |
| **AI 새 점부** | **0.0147** (1.8배) |

푸아송·볼피벗은 **균일 밀도를 전제**한다. 성긴 쪽에서 이면각이 뛴다 —
푸아송 11.7~12.9° · 볼피벗 **31.9°** (관측 3.04° · v22 2.25°). **4~10배 거칠다.**
볼피벗은 아예 부서진다.

### 그리고 둘을 더 잃는다

| | |
| --- | --- |
| **원본 텍스처** | 정점을 전부 새로 만드니 UV 가 날아간다. 다시 구워야 한다 |
| **출처 분리** | 관측과 AI 가 **한 표면으로 녹는다.** `region_observed` / `region_ai` 를 못 나눈다 |

두 번째가 결정적이다. `NFR-ETH-003` 을 **구조적으로** 못 지킨다.
그래서 출력 노드 이름을 `region_fused` 로 뒀다 — **이름이 곧 한계다.**

> **결론.** 격자를 빼도 *"가정이 없어지는 것"* 이 아니다. 모델 자체가 굽다리바리
> 16형상만 보고 배웠으니 **암묵적 가정은 그대로 남는다.** 사라지는 것은
> 가정이 아니라 **투창을 지킬 수단과 출처를 가를 수단**이다.
>
> 다만 **모델은 잘못이 없다.** 모델은 투창 칸을 73% 열어 두고 있었다 (§5.6.3).
> 그 의도를 **재구성 단계가 뭉갠다.**

재현: `versions.py --build v23a`(~`v23d`) · 코드 `make_mesh_direct.py` · `open3d` 필요.

## 5.13 잣대를 스크립트로 옮겼다 (2026-09-18)

지표 다섯이 **일회성 스크립트**에 있었다. 그래서 버전마다 자동으로 안 재졌고,
`파이프라인.md` 의 표에 **v15 값이 v22 자리에** 남아 있었다.
`versions.py --measure` 로 옮겼다.

| 새로 자동 측정 | 무엇 |
| --- | --- |
| **면 어긋남** | 같은 높이에서 AI 바깥벽 − 관측 바깥벽 (mm). 음수면 파묻힘 |
| **θ 흔들림** | 한 행 안에서 **바깥벽 반지름**이 각도에 따라 흔들리는 정도 (변동계수) |
| **벽 두께** | 칸 안에서 `r` 을 정렬해 가운데 빈 틈에서 자른 값. 관측 대비 % |
| **투창 열림 %** | 투창 칸 중 최종 메시가 안 덮은 비율 |
| **결손 메움 %** | 결손 칸 중 최종 메시가 덮은 비율 |

**격자는 원본 메시에서 만든다.** 예측 npz 를 안 봐도 되고, 무엇보다
**버전끼리 같은 잣대**가 된다 — 예측이 바뀌어도 투창 자리는 안 바뀐다.
검증: v22 에서 투창 **1,862칸**이 나와 파이프라인 값과 정확히 일치했다.

### 고친 것 — 안쪽벽과 바깥벽이 섞여 있었다

처음 구현은 칸 안 반지름을 통째로 썼다. **이 유물은 두께 있는 껍질이라 한 칸에
안쪽벽과 바깥벽이 같이 들어간다.** 그대로 변동계수를 내면 울퉁불퉁함이 아니라
**벽 두께**를 재게 된다.

| θ 흔들림 (v22) | 섞어서 | **바깥벽만** |
| --- | ---: | ---: |
| AI | 0.0793 | **0.0110** |
| 관측 | 0.0716 | **0.0333** |

바깥벽만 쓰니 관측 0.0333 이 §5.8.1 의 0.0319 와 맞는다. 면 어긋남도
−3.53mm → **−1.3mm** 로 §5.8.1 의 −1.33mm 와 맞았다.

### 그런데 벽 두께는 안 맞는다 — 71~72%

| | |
| --- | ---: |
| 이 측정 (v15~v22 전부) | **71~72%** |
| §5.8.1 이 적어 둔 값 | 110% |
| 관측 절대값 — 이 측정 | 5.75mm |
| 관측 절대값 — §5.8.1 | 5.88mm |

**관측은 맞는데 AI 쪽이 다르다.** 표본을 80만 → 200만으로 늘려도 72~73% 로
안정적이라 **노이즈가 아니다.** §5.8.1 의 110% 가 낡은 측정이거나 정의가 달랐다.
어느 쪽이 맞는지는 아직 못 갈랐다 — **일단 이 측정을 표준으로 두고 그렇게 적는다.**

### 버전별로 보면

```
      어긋남   θ흔들림  두께%  투창열림
v15    -0.8   0.0152    71    99.0
v18    -0.9   0.0114    71    99.4     ← v3 가중치
v21    -1.0   0.0110    71    98.8
v22    -1.3   0.0110    72    90.4     ← 투창열림이 뚝 떨어진다
```

**v22 의 투창 열림 90.4% 는 나빠진 것이 아니다.** `--fix-strut` 이 깨진 가로살
자리(184칸)를 **일부러 결손으로 되돌려** 메웠기 때문이다 (§5.11). 지표가
그 변화를 정확히 잡아낸 것이다. **숫자가 낮다고 나쁜 게 아닌 유일한 열이다.**

## 5.14 정밀도를 넣으니 v2 가 v1 보다 못했다 (2026-09-18)

주 지표인 **커버리지 순증은 재현율**이다. 짝인 **정밀도가 없었다.**

`n_new_valid`(유효 보충점)를 **세고 있었는데 비율로 안 쓰고 있었다.**
`precision = n_new_valid / n_new` 한 줄이면 되는 것이었다.

### 먼저 — 이 지표를 믿을 수 있나

자체 테스트에 **무작위 산포** 대조군을 더했다. 입력은 그대로 두고 나머지를
바운딩 상자 안에 균등 무작위로 뿌리는 **가장 멍청한 모델**이다.

| | 순증 (재현율) | 정밀도 |
| --- | ---: | ---: |
| 완벽 (`pred=complete`) | 1.000 | **0.997~1.000** |
| **무작위 산포** | **0.017~1.000** | **0.002~0.127** |
| 아무것도 안 함 (`pred=partial`) | 0.000 | — |

**커버리지는 속는다.** 무작위가 `side` 에서 순증 **1.000**, `rim` 에서 0.960 을 받는다.
δ 가 정답 점간격의 3배(≈5mm)라 부피에 6,000점을 뿌리면 어지간한 정답점 근처에
뭔가가 걸린다. 결손이 작고 뭉친 패턴일수록 심하다.
(`bottom` 만 0.017 로 안 속는다 — 굽이 통째로 없어 **입력 상자 밖**으로 메워야 한다.)

**정밀도는 안 속는다.** 완벽 0.99 vs 무작위 0.03 — 자릿수가 다르다.

> **둘은 짝이다.** 재현율만 보면 뿌리는 것을 못 잡고, 정밀도만 보면 **확실한 데만
> 조금 찍고 마는 것**을 못 잡는다. 실제로 `base` 는 정밀도 0.766 인데 순증이 0.092 다 —
> 거의 안 만들고 만든 것만 맞혔다. F-Score 가 둘을 묶는다.

### 그 과정에서 — 지금까지 누출된 자로 잰 것을 발견했다

`make_pairs.normalize()` 는 `partial` 을 **`complete` 의 중심·축척**으로 저장한다.
그리고 `run_adapointr.py --self-normalize` 는 **기본이 꺼짐**이다.
안 걸고 돌리면 조용히 §4.5 의 누출된 값이 나온다.

| `base` (파인튜닝 안 함) | 누출된 자 | **자기 정규화** |
| --- | ---: | ---: |
| `rim` 순증 | 1.000 | **0.257** |
| `ragged` 순증 | 0.720 | **0.102** |
| `slant` 순증 | 0.944 | **0.036** |

**§4.5 가 그대로 재현됐다** (0.102). 누출을 가장 깔끔하게 보여주는 실증이기도 하다 —
파인튜닝을 전혀 안 한 모델이 액자만 주면 순증 1.000 을 받는다.

### 네 모델을 같은 1,920쌍에 (자기 정규화)

`eval_all_models.py` 를 새로 만들었다. 전에 v2(900쌍)와 v3(1,920쌍) 표를 나란히
놓은 적이 있어 **구조적으로** 막는다.

| 결손 있는 1,600쌍 전체 | base | v1 | v2 | **v3** |
| --- | ---: | ---: | ---: | ---: |
| 순증 (재현율) | 0.092 | 0.938 | **0.999** | 0.996 |
| **정밀도** | 0.766 | 0.918 | 0.823 | **0.949** |
| **F순증** | 0.165 | 0.914 | 0.870 | **0.962** |
| 과채움 (`none` 보충점) | 1 | 7 | 10 | 9 |

**v2 가 v1 보다 못하다.** 순증만 보면 v2 가 0.999 로 1등인데 정밀도가 0.823 으로
v1(0.918)보다 낮다. **재현율을 정밀도와 바꿔치기한 것**이었다.
순증 하나만 보던 때는 이것을 개선으로 읽었다.

**v3 는 양쪽 다 잡았다** — 순증 0.996 + 정밀도 0.949. 5패턴 중 4개에서 F순증 최고.
`slant` 는 0.069 → 0.286 → 0.590 → **0.974**.

과채움 대조군은 전부 통과했다. 완형을 넣었을 때 보충점이 1~10개뿐이다.

### 값이 높은 이유 — 학습 형상을 포함해서가 아니다

의심이 들어 갈라 봤다. 학습은 형상 14개, 검증은 `경주_887`·`대구대_1834` 둘이다.

| F순증 | base | v1 | v2 | **v3** |
| --- | ---: | ---: | ---: | ---: |
| 학습에 쓴 14형상 (1,400쌍) | 0.171 | 0.919 | 0.869 | 0.964 |
| **검증용 2형상 (200쌍)** | 0.097 | 0.902 | 0.887 | **0.949** |

v3 가 0.964 → 0.949 로 **0.015 밖에** 안 떨어진다. v2 는 오히려 오른다.
**학습 데이터 포함 탓이 아니다.**

진짜 이유는 넷이다.

| | |
| --- | --- |
| ① **형상 홀드아웃이 사실상 홀드아웃이 아니다** | 16형상이 **전부 굽다리바리**다. 2개를 빼도 나머지가 거의 같은 형태라 *"못 본 형상"* 이 *"못 본 굽다리바리"* 일 뿐이다. **기종을 벗어나는지는 이 평가로 못 안다** — 기종 밖 시험(`EA_028` 항아리)은 이미 결실부 출력점 **0개**로 실패했다 (§3) |
| ② 결손이 합성이다 | 3D 를 깔끔한 면으로 깎았다. 실제 파단면은 거칠다. sim-to-real 갭은 미검증 (§5.6.5) |
| ③ δ 가 관대하다 | 점간격의 3배 ≈ 5mm |
| ④ 학습 완형이 TRELLIS 산출물이다 | 실제 유물보다 매끄러워 예측하기 쉽다 |

> **이 표는 *"굽다리바리를 깔끔하게 깎았을 때"* 의 성능이다.**
> 그 조건 안에서는 진짜다(홀드아웃으로 확인). **그 밖은 이 표가 말하지 않는다.**

### 곁들여 고친 것

- 패턴 목록이 코드에 박혀 있어 **`slant` 가 표에서 통째로 빠져** 있었다. v3 의 핵심 패턴이다.
  데이터에서 따도록 고쳤다.
- F-Score 를 둘로 낸다 — `F생`(생 재현율, 문헌 비교용) · `F순증`(바닥값 보정, 버전 비교용).

재현: `eval_completion.py --self-test` (대조군 셋) ·
`eval_all_models.py base=… v1=… v2=… v3=…`

## 5.15 진짜 테스트 세트를 만들었다 (2026-09-19)

§5.14 까지의 숫자에는 구멍이 있었다. **테스트 세트가 없었다.**

```
train   14형상   가중치를 학습
val      2형상   **에폭을 골랐다** (v3 = ep8, 커버리지 이득 기준)
test      없음   ← 아무 데도 안 쓴 형상이 없다
```

`val` 로 성능을 보고하면 낙관적이다 — 그 2형상으로 에폭을 골랐기 때문이다.

### 먼저 — 중앙값 하나로 요약하면 속는다

§5.14 에서 v1 의 검증 F순증을 **0.902** 로 적었다. 깊이별로 가르니:

| 결손률 | 쌍 | v1 |
| --- | ---: | ---: |
| 0.00~0.20 | **114** | 0.943 |
| 0.50~0.65 | 21 | **0.236** |

**검증 쌍의 절반이 결손률 0.20 미만**이라 중앙값이 쉬운 구간에 앉았다.
문서의 *"v1 깊은 결손 0.179"* 와 맞는 것은 0.236 쪽이다.
`eval_all_models.py` 가 이제 **깊이별 표를 기본으로** 낸다.

### 테스트 형상 셋 — 학습에도 에폭 선택에도 안 썼다

완형 후보 24점 중 16점만 학습에 썼다. 남은 것에서 골랐다.

| | 전체 결손 | 아가리 | 몸통 | 굽 |
| --- | ---: | ---: | ---: | ---: |
| **경주_4614** | **0.1%** | 0.9% | 0.0% | **0.0%** |
| **경주_4614_2** | 1.0% | 6.7% | 0.0% | **0.0%** |
| **경주_8480** | 2.2% | 7.7% | 0.2% | 2.4% |

**`경주_4614` 는 완형 후보 24점에 아예 없었다.** 메타가 완형으로 안 잡았는데
실측하니 0.1% 다 — 학습에 쓴 16점 중 어느 것보다 온전하다.
메타를 못 믿는다는 §5.11 의 판단과 같은 이야기다.

> **후보를 부위별로 재는 것이 필요했다.** 전체 결손률만 보면
> `경주_8477`(1.4%)·`경주_6312`(2.3%) 도 깨끗한데 **아가리가 각각 6.0%·13.4%** 다.
> `make_pairs.py` 주석이 *"지표가 가장 깨끗한데 사진을 보면 아가리가 크게 이빠져 있다"*
> 고 이미 적어 두었던 것과 맞는다. 아가리는 격자에서 맨 위 몇 행뿐이라
> **전체 비율로는 작게 나온다.**
>
> `경신_71212`(handled)·`경신_71885` 는 **굽이 깨져**(7.7%·21.9%) 뺐다.
> 굽은 투창 구조가 있어 깨지면 n-fold 판정 자체가 흔들린다.
> **그래서 테스트에 손잡이 기종이 없다 — 한계로 적어 둔다.**

`make_pairs.py --only` 를 추가했다 (완형 필터를 건너뛴다).
쌍 **360개** = 3형상 × 6패턴 × 20, 씨앗 777 (학습 쌍의 0 과 겹치면 안 된다).

## 5.16 AI 가 찍은 점이 실제로 무슨 일을 하나 (2026-09-20)

**빈 칸이면 어차피 다 메우는데 AI 점이 의미가 있나** — 물어볼 만한 질문이라 재 봤다.

### 먼저 — 헷갈리는 자리를 풀어 둔다

*"모델이 투창 칸에 점을 안 찍으니 투창은 저절로 지켜지지 않나"* 가 아니다.

```
모델이 투창 칸에 점을 안 찍는다        ← 사실. 새 점 0개
   ↓
그 칸은 "점이 없다"
   ↓
격자 규칙:  점 없는 칸 = 결손          ← 여기서 뒤집힌다
   ↓
결손이니 R 을 정해야 한다
   ↓
AI 점이 없으니 **이웃에서 보간**
   ↓
면이 생긴다 = 투창이 막힌다
```

**점군에는 "여기는 원래 뚫려 있다" 와 "여기는 없어졌다" 를 가를 정보가 없다.**
`n-fold` 판정이 그 정보를 밖에서 넣는 것이다 (§5.11).

### 그래서 AI 는 "어디를" 이 아니라 "어떤 모양으로" 를 정한다

| 질문 | 누가 정하나 |
| --- | --- |
| **어디를 메울까** | 관측 점유. **AI 무관** |
| **어떤 반지름으로 메울까** | **AI 점** — 패치의 46% 에 직접 값을 준다 |

```python
R[h,θ] = median(그 칸의 AI 점 반지름)    # 점이 있으면
R[h,θ] = fill_unknown(이웃 평균)          # 없으면 보간
```

### 재 봤다 — AI 를 빼고 보간만으로 채우면

같은 패치(14,061칸)를 두 번 만든다. 한 번은 AI 점을 쓰고, 한 번은 관측 경계만 쓰고 나머지를 전부 보간한다.

| R 이 얼마나 달라지나 | |
| --- | ---: |
| 중앙 | **4.63mm** |
| 90분위 | **22.91mm** |
| 최대 | **35.41mm** |
| *참고 — 벽 두께* | *5.7mm* |
| *참고 — 관측 점간격* | *0.7mm* |

**중앙값이 벽 하나 두께만큼**이다. 90분위 23mm 는 형상이 아예 달라지는 크기다.

패치 14,061칸 중 **6,425칸(46%)** 에 AI 가 직접 값을 주고, 나머지 54% 도
그 칸들을 **경계로 삼아** 보간되므로 AI 값이 바뀌면 같이 바뀐다.

### 왜 보간만으로는 안 되나

라플라스 보간은 **경계를 매끄럽게 잇는 것**뿐이다. 경계에서 멀어질수록 정보가 없어 평평해진다.

```
좁은 결손   경계가 가까워 보간으로도 비슷하게 나온다
넓은 결손   경계가 멀어 밋밋해진다.  AI 가 "여기쯤 부풀어야 한다" 를 준다
```

그것이 90분위 22.91mm 의 정체다 — **크게 없어진 데서만 벌어진다.**

> **§5.15 의 표와 같은 이야기다.** 얕은 결손(0.00~0.20)에서는 v1 0.899 · v3 0.895 로
> 사실상 동률인데, 깊은 결손(0.50~0.65)에서 v1 **0.229** · v3 **0.918** 로 갈린다.
> **보간으로 되는 구간과 안 되는 구간이 거기서 나뉜다.**

재현: `work/pred_71489_A_normal_v3tta8.npz` 로 격자를 만들고
`R` 을 두 번 채워 비교한다 (AI 점 사용 / 관측 경계만).
