# 기존 형상 복원 검수에 추가한 도구 사용 안내

dev에는 원래부터 복원 결과를 비교·평가하는 도구가 있다. 이 폴더는 그 검수 체계를 대체하거나
처음 만든 것이 아니라, 기존 평가에서 직접 확인하지 않던 두 가지를 보완한다.

| 구분 | 도구 | 확인하는 것 |
|---|---|---|
| 기존 검수 | `completion/eval_completion.py` | 결손부 커버리지와 Chamfer |
| 기존 검수 | `completion/versions.py` | 복원 버전별 형상·이음새·색 비교 |
| 기존 검수 | `rotational/compare_material.py` | 관측부와 채움부의 색·질감 차이 |
| 기존 검수 | `rotational/render_check.py` | 입력 사진과 렌더의 실루엣 IoU |
| 기존 검수 | `rotational/build_mesh_direct.py --fill-compare` | 채움 방식별 평활도 대조 |
| 이번에 추가 | `mesh_preflight.py` | 복원 전에 GLB의 scene transform·좌표계·단위를 올바르게 읽었는지 |
| 이번에 추가 | `audit_result.py` | 복원 후에 원본 관측 형상의 정점과 face가 그대로인지 |

즉, 기존 도구는 주로 **새로 채운 부분의 품질**을 평가하고, 이번에 추가한 두 도구는 그 평가에
들어가기 전의 **입력 해석**과 평가가 끝난 뒤의 **원본 보존**을 확인한다. 두 도구 모두 입력 GLB를
수정하지 않고 JSON 보고서만 만든다. 실행에는 Python, NumPy, trimesh가 필요하다.

## 1. 복원 전: 입력 GLB 사전검사

현재 dev처럼 glTF의 Y-up 좌표를 그대로 사용하는 경우:

```powershell
python mesh_preflight.py "C:\data\A_normal.glb" `
  --out "C:\data\A_normal.preflight.json" `
  --source-space GLTF_WORLD_Y_UP `
  --working-space GLTF_WORLD_Y_UP `
  --unit-status normalized_only
```

Blender 단계처럼 Z-up 좌표가 필요할 때만 `--working-space BLENDER_WORLD_Z_UP`을 사용한다.
이 옵션을 사용하면 도구가 Y-up→Z-up 변환을 보고서에 기록한다. 이후 단계에서 같은 변환을 다시
적용하면 안 된다.

보고서의 핵심 필드는 다음과 같다.

- `status`: `PASS`면 기본 구조와 transform 검사를 통과했다.
- `scene.nodes[].transform`: GLB node에 들어 있던 변환행렬이다.
- `working_mesh.bounds`: node transform과 좌표 변환을 적용한 실제 작업 좌표의 범위다.
- `units.metric_scale_verified`: 실제 mm 단위가 검증됐는지 나타낸다.
- `units.mm_metrics_allowed`: `false`면 결과를 mm 정확도로 표현하면 안 된다.

`normalized_only`와 `unknown`은 오류가 아니다. 단위가 확인되지 않았다는 사실을 숨기지 않고,
후속 코드가 bbox 비율이나 점 간격처럼 상대적인 기준을 사용하도록 알려주는 상태다.

## 2. 복원 후: 원본 관측 형상 불변 검사

```powershell
python audit_result.py `
  --source "C:\data\A_normal.glb" `
  --result "C:\data\A_normal_2node.glb" `
  --config "C:\data\run-config.json" `
  --out "C:\data\A_normal_2node.audit.json"
```

기본적으로 결과 GLB의 `region_observed`를 입력 GLB와 비교한다. 회전 대조군처럼 노드명이
`region_carried`이면 자동으로 그 노드를 확인하며, 필요하면
`--observed-node region_carried`로 직접 지정할 수 있다.

보고서의 핵심 필드는 다음과 같다.

- `status`: 관측부 정점과 face가 모두 같으면 `PASS`, 하나라도 달라지면 `FAIL`이다.
- `observed_geometry.max_vertex_delta`: 입력과 결과 관측부 사이의 최대 정점 이동량이다.
- `observed_geometry.faces_equal`: face 인덱스와 순서가 같은지 나타낸다.
- `source`, `result`, `configs`: 재실행 대상을 확인할 수 있는 SHA-256이다.
- `ground_truth.status`: 독립 GT를 주지 않았으면 `NOT_EVALUATED_NO_INDEPENDENT_GT`다.

기본 검사는 정점이 정확히 같은지를 본다. 파일 변환 과정의 허용 가능한 반올림 오차가 확인된
경우에만 `--atol`로 허용치를 명시한다.

## 3. 기존 검수에 무엇이 추가됐는가

| 구분 | 답하는 질문 | 대표 도구 |
|---|---|---|
| 기존 품질 평가 | 결손부를 얼마나 잘 채웠고, 경계·재질·실루엣이 얼마나 자연스러운가 | `completion/eval_completion.py`, `completion/versions.py`, `rotational/compare_material.py`, `rotational/render_check.py`, `rotational/build_mesh_direct.py --fill-compare` |
| 추가 입력 검사 | 품질 평가에 들어갈 GLB를 좌표계·transform·단위 관점에서 올바르게 읽었는가 | `mesh_preflight.py` |
| 추가 산출물 감사 | 복원 과정에서 보존해야 할 원본 관측 형상을 바꾸지 않았는가 | `audit_result.py` |

따라서 `mesh_preflight.py`가 `PASS`라고 해서 축 추정이나 복원이 정확하다는 뜻은 아니다.
`audit_result.py`가 `PASS`라고 해서 생성한 결손부가 역사적으로 맞다는 뜻도 아니다. 두 도구는
기존 검수 결과를 대체하지 않는다. 비교 실험의 입력 조건과 원본 보존 여부를 추가로 확인하고,
실제 복원 품질 판단은 기존 평가 도구의 결과를 그대로 사용한다.
