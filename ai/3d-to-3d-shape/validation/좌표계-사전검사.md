# 좌표계·scene transform·단위 사전검사

## 목적

축이나 복원 성능을 높이는 기능이 아니라, 입력 GLB를 잘못 읽은 상태에서 후속 실험이 진행되는 것을
막는다. raw `POSITION`만 읽으면 scene-node transform이 빠질 수 있고, glTF Y-up 좌표를 Blender
Z-up 좌표처럼 해석하면 높이·축·ROI가 모두 달라진다.

## 검사 범위

`mesh_preflight.py`는 다음을 JSON으로 남긴다.

1. 입력 파일 SHA-256
2. 모든 geometry node의 4×4 transform과 identity 여부
3. node transform의 `local -> world -> local` 왕복 오차
4. scene transform을 적용한 world mesh의 bbox·centroid·정점·면 수
5. glTF Y-up과 Blender Z-up 사이에 적용한 명시적 변환행렬
6. 단위 상태와 mm 지표 사용 가능 여부

도구는 축이나 물리 단위를 추측하지 않는다. 실제 mm 근거가 없다면 `normalized_only` 또는
`unknown`으로 실행해야 하며, 이때 보고서의 `mm_metrics_allowed`는 `false`다.

## 실행

현재 dev처럼 glTF world Y-up을 그대로 작업 좌표로 사용할 때:

```powershell
python mesh_preflight.py A_normal.glb `
  --out A_normal.preflight.json `
  --source-space GLTF_WORLD_Y_UP `
  --working-space GLTF_WORLD_Y_UP `
  --unit-status normalized_only
```

Blender Z-up 좌표가 필요한 별도 단계일 때만 변환을 한 번 선언한다.

```powershell
python mesh_preflight.py A_normal.glb `
  --out A_normal.blender-z-up.preflight.json `
  --source-space GLTF_WORLD_Y_UP `
  --working-space BLENDER_WORLD_Z_UP `
  --unit-status normalized_only
```

이 보고서를 사용하는 후속 코드가 같은 Y-up→Z-up 변환을 다시 적용하면 안 된다.

## 합격 기준

- 상태가 `PASS`
- 빈 메시 또는 비유한 정점이 없음
- node transform이 역변환 가능함
- 왕복 오차가 설정 허용치 이내
- 좌표 변환 적용 여부가 manifest와 실행 명령에서 일치함
- 검증되지 않은 단위에 mm 정확도 문구를 사용하지 않음

## 현재 dev에 필요한 수준

전체 사전검사 프레임워크를 새로 만들 필요는 없다. 이 스크립트와 JSON 한 개를 각 입력의 최초
실행 전에 생성하고, `completion/`과 `rotational/`이 동일한 좌표 선언을 사용하는지만 확인한다.
