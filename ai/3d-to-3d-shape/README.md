# 3D → 3D 형상 복원

손상 3D 메시의 결손부를 채운다. 명세 §3 의 3단계 중 **② 모델 복원** 자리다.

- 담당: 기여자
- 대상 검증 유물: 굽다리바리 경주 신수 71489
- 관련 요구사항: `FR-AI-003` · `NFR-ETH-001` ~ `NFR-ETH-004`
- 갱신: 2026-09-19

세 갈래를 **같은 유물에 나란히 시도했다.** 폴더를 나눈 이유가 그것이다.

| 폴더 | 방법 | 학습 | 상태 |
| --- | --- | --- | --- |
| [`completion/`](completion/) | AdaPoinTr 점군 완성 + `(h,θ)` 격자 메시화 | **있음** | **현행 · v3 가중치 · v22 메시** |
| [`rotational/`](rotational/) | 회전대칭 원통 전개 + 이중조화 | 없음 | **대조군** — 지금도 비교에 쓴다 |
| [`shape-prior/`](shape-prior/) | 랜드마크 정렬 + PCA 통계 형상 모델 (굽다리바리 43점) | 없음 | **보류** — 71489 에는 불필요 |

> **2026-09-16 에 결론이 뒤집혔다.** 이 문서는 한동안 `completion/` 을 *"경로 종결"*,
> `rotational/` v32 를 *"현행"* 이라고 적고 있었다. 그때는 맞는 판단이었다 —
> 파인튜닝 v1 이 실제 유물에서 보충점 253개에 그쳤다.
> 그 뒤 학습 데이터와 체크포인트 선택을 고치면서 뒤집혔다. 아래에 근거를 적는다.

## 어느 것을 쓰나

**`completion/` 이 현행 복원 경로다.**

```text
사진 1장
  └─[A] TRELLIS.2 ──────────→ 손상 GLB                    ① 손상 상태 3D
                                   │
                                   ▼
     [B] completion/  AdaPoinTr v3 추론 + 회전 TTA 8회      점 65,536개
                                   │
                                   ▼
     [C] completion/  (h,θ) 144x216 격자 → 2노드 메시화     ② 복원 3D
                      region_observed (원본 무수정)
                      + region_ai (결손부만)
```

학습 줄기는 따로 돈다 — 완형을 3D 에서 깎아 쌍을 만들고
ShapeNet-55 사전학습 위에 파인튜닝한다 (`AdaPoinTr_gupdari_v3.pth`).

**형상 단위로 나눈다.** 쌍으로 나누면 같은 유물이 학습과 평가에 같이 들어간다.

| | 형상 | 쌍 | |
| --- | ---: | ---: | --- |
| train | 14 | 1,680 | 가중치 학습 |
| val | 2 | 240 | 에폭 선택 |
| **test** | 3 | 360 | **보고용. 학습에도 에폭 선택에도 안 썼다** |
| 합 | **19** | **2,280** | |

자세한 것은 [`completion/파이프라인.md`](completion/파이프라인.md) (현재형) ·
[`completion/결과.md`](completion/결과.md) (시간순 기록) ·
[`completion/README.md`](completion/README.md) (설명과 그림).

## 무엇이 뒤집었나

**① 벤치마크 누출을 찾았다.** `partial` 을 `complete` 의 좌표계로 정규화하면
모델이 **원래 크기를 액자에서 읽는다.** 같은 쌍·같은 가중치로 정규화만 바꾸니
커버리지 순증이 **0.700 → 0.102** 로 무너졌다. ShapeNet-55 가 그렇게 만들어져 있다.
이걸 모르고는 어떤 수치도 믿을 수 없었다.

**② 체크포인트를 val CD 가 아니라 결손부 커버리지로 골랐다.** CD 는 계속 내려가는데
정작 결손을 메우는 능력은 다른 에폭에서 최고였다. v3 는 ep8 채택 — CD 로 골랐으면
ep12 를 골랐을 것이다.

**③ 학습 분포가 얕았다.** 깊은 결손이 안 되는 것은 모델이 아니라 데이터 탓이었다.
완형을 9 → 16 형상으로 늘리고 `slant`(비스듬한 절단) 패턴을 넣자:

**테스트 세트 360쌍 · 깊이별 F순증** (재현율과 정밀도의 조화평균):

| 결손률 | 사전학습 | v1 | v2 | **v3** |
| --- | ---: | ---: | ---: | ---: |
| 0.00~0.20 | 0.641 | **0.899** | 0.836 | 0.895 |
| 0.35~0.50 | 0.082 | 0.438 | 0.586 | **0.936** |
| **0.50~0.65** | 0.026 | 0.229 | 0.625 | **0.918** |

**v3 의 이득은 전부 깊은 쪽에 있다.** 얕은 결손에서는 v1 과 사실상 동률이다.
재현율만 보면 속는다 — 무작위로 점을 뿌리는 대조군이 `side` 에서 순증 1.000 을
받는다 (정밀도 0.042). 자세히: `completion/결과.md` §5.14 · §5.15

**④ 출처 분리를 메시화에서 풀었다.** 아래 provenance 문제가 남아 있었는데,
`(h,θ)` 격자가 칸 단위로 출처를 들고 있어 **관측부는 원본 메시 그대로**
(V=94,877 F=149,150 무수정) 내보내고 AI 가 만든 면만 별도 노드로 뺀다.
푸아송 같은 표면재구성을 썼으면 둘이 한 표면으로 녹아 이게 불가능했다.

> **provenance 는 여전히 갈래마다 다르다.** `rotational/` 은 근거가
> "이 유물 자신의 회전대칭"이고 `shape-prior/` 는 "참조한 유물 N점"이라 **열거 가능**하다.
> 학습 완성은 그 수준으로 못 좁힌다 — 다만 **어느 면이 추정인지는 면 단위로 분리**했다
> (`NFR-ETH-003`). 어느 완형에서 왔는지까지 대는 것은 아직 못 한다.

## 나머지 둘

### `rotational/` — 대조군으로 계속 쓴다

생성 모델 없이 **회전대칭과 n-fold 투창 주기**라는 검증 가능한 가정만으로 채운다.
근거를 열거할 수 있다는 점에서 `completion/` 보다 강하다.

지금은 **대조군 역할**이다. `completion/` 이 회전대칭을 *가정하지 않고* 얼마나
가까이 가는지를 재는 기준선이다 (점군 그림의 `v32` 패널이 이것).
`rotational/` 의 투창 `n-fold` 판정 기준은 `completion/` 이 그대로 가져다 쓴다.

### `shape-prior/` — 필요해질 때까지 보류

형상 사전은 **프로파일의 절반 이상이 사라진 유물**에 필요한 도구다. 71489 는 프로파일이
대체로 살아 있어서 불필요했다. 실패가 아니라 **착수 시점이 일렀다.**

다만 부산물이 현행 경로에 실제로 쓰인다 — `meta/artifacts.csv` (43점 치수·투창 구조)가
투창 `n-fold` 판정의 문헌 근거이고, `trellis3d/` 완형 42점이 **학습 데이터의 원천**이다.

공개 저장소에는 **스크립트·기록 JSON·근거 그림만** 커밋한다.
각 폴더의 `.gitignore` 가 무엇을 왜 뺐는지 적어 두었다.

| AdaPoinTr 가중치 (`completion/ckpts/`, 868MB) | 공유 스토리지 |
| e뮤지엄 원본 사진 43점 (`images/`, 28MB) | 공유 스토리지 — 출처는 `shape-prior/meta/artifacts.csv` |
| AI-Hub 211-2 원본 | 각자 받는다. 환경변수 `AIHUB_211_2_ROOT` |
| TRELLIS.2 설치본 | 각자 받는다. 환경변수 `TRELLIS2_HOME` |

`completion/` 을 돌리려면 원본 사진·완형 3D 가 있는 곳을 `RESTORE_ROOT` 로 건다.
안 걸면 스크립트 옆을 본다. 산출물 위치는 `ADAPOINTR_WORK`.
